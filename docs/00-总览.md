# AMuBBS 文档总览

## 0.1 这是什么

AMuBBS 是一个**零依赖的 PHP 论坛**：一个能扔到共享虚拟主机上、上传即用的轻量论坛程序。

「零依赖」不是口号，而是硬约束，所有设计选择都从这张表推导出来：

| 约束 | 后果 |
| --- | --- |
| 无 root、无 shell | 不能装扩展、不能跑构建、不能改系统配置 |
| 无 Composer / npm / Node | 第三方库必须要么自带（vendored）、要么不引入 |
| 无 Redis（可选） | 缓存必须能在「只有一个可写目录」的情况下工作 |
| 无系统 cron | 定时任务要能通过一次 HTTP 请求触发 |
| 无常驻进程 | 队列要在请求生命周期内消费，不能靠 worker |
| 小机器 / 共享空间 | 单页 CSS+JS 要克制，缓存与 SQL 次数都要算 |

代码体量：257 个 PHP 文件 / 约 4.6 万行，`app/ core/ config/ resources/ install/ scripts/` 合计约 1.7 MB。
自研 CSS 约 147 KB、JS 约 212 KB（含 htmx），后台 vendor 资源约 1.2 MB。

## 0.2 环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| PHP | **8.0+**（建议 8.2） | 安装向导会校验，低于 8.0 直接拦下 |
| PHP 扩展 | `pdo` `pdo_mysql` `mbstring` `json` | 缺任何一个装不上 |
| 可选扩展 | `redis`（有则自动用，没有就用文件缓存）、`Zend OPcache`（提速） | 都不装也能跑 |
| 数据库 | **MySQL 5.6+ / MariaDB 10+**（建议 MySQL 5.7+ / MariaDB 10.11） | 不用 FULLTEXT 也能搜索（见 0.9） |
| Web 服务器 | Apache / Nginx / 主机面板自带的都行 | `public/.htaccess` 与 `public/.user.ini` 已带 |
| 可写目录 | `storage/`、`public/uploads/` | 共享主机常见坑：只给读权限就会白屏 |

## 0.3 安装（三步）

1. **上传**：把项目传到主机，把网站根目录指向 **`public/`**。
   `storage/` 必须留在 Web 根目录之外（否则缓存文件可能被直接下载）。
2. **打开** `https://你的域名/install`，按向导填数据库信息 → 自动建表、建管理员、写 `install/install.lock`。
3. **进后台**：`/admin`，用向导里创建的管理员账号登录。

不想用向导就按 [`install/INSTALL.md`](../install/INSTALL.md) 手动来（导入 `install/database.sql`、
写 `.env`、建 `install/install.lock`），共享主机的注意事项也都写在那份文档里。

`.env` 通常只需要填 `DB_*` 与 `APP_KEY`（复制 `.env.example`）。
`.env.example` 里的每一项都由代码真实读取——`php scripts/check_env.php` 会守住这一点，不留「写了不读」的死配置。

## 0.4 定时任务怎么办（没有系统 cron）

访问下面这个地址就等于跑一次全部定时任务：

```
https://你的域名/cron/run?key=<cron_key>
```

- `cron_key` 在后台 **系统设置** 里配置（留空表示不校验，但不建议）。
- 触发方式三选一：主机面板自带的「计划任务」填这个 URL；或用外部定时服务
  （UptimeRobot、cron-job.org 之类）每 5–10 分钟访问一次；或者需要时手动访问。
- 任务清单（`CronSvc::runAll()`，带原子锁防止并发）：

| 任务 | 作用 |
| --- | --- |
| `clean_attachments` | 清理没有关联帖子的临时附件 |
| `update_forum_stats` | 重算板块的帖子/主题计数 |
| `clean_ip_blacklist` | 清理已过期的 IP 封禁 |
| `reset_today_stats` | 跨天时把「今日发帖」计数归零 |
| `flush_views` | 把浏览计数批量落库 |
| `warm_cache` | 预热首页/板块缓存 |
| `clean_ip_access` | 清理 7 天前的 IP 频率记录 |
| `clean_old_logs` | 清理 90 天前的操作日志 |
| `process_queue` | 消费邮件/通知队列 |
| `release_stale_jobs` | 释放超时未完成的队列任务 |

**不配定时任务也能正常用**：文件缓存自带惰性 GC（过期数据在读写时顺手清理），
上面这些只是「保洁 + 队列」的优化项。

## 0.5 技术栈（现状）

| 层 | 选型 |
| --- | --- |
| 后端 | PHP 8 + 自研微框架（`core/`，24 个类；Bootstrap / Router / Database / Cache / Event） |
| 数据库 | MySQL / MariaDB，PDO 预处理；可选读写分离（`DB_READ_HOST`） |
| 缓存 | 文件缓存（默认，零扩展）或 Redis；`CACHE_DRIVER=auto` 自动选择 |
| 会话 | 文件（默认）或 Redis（多节点共享登录态） |
| 前台 | **htmx 2.0.11** 做增量更新 + 自研 CSS（无 Alpine、无 Layui、无构建步骤） |
| 后台 | **layuimini v2 + Layui 2.6.3 + Font Awesome 4.7**，iframe 多标签外壳（layui 只在后台加载，前台不加载） |
| 插件 | WordPress 风格钩子：`add_action` / `apply_filters`，零依赖，后台可启停 |
| 队列 | 数据库表 `queue_jobs`，由 `/cron/run` 触发消费（无 Redis 也能用） |

历史选型里的 Alpine.js 与 TinyMCE 已经移除；**Layui 没有被移除**——它现在只服务后台
（layuimini 外壳与子页面），前台一个字节都不加载。原因与取舍见 [`06-前端选型.md`](06-前端选型.md)。

## 0.7 目录结构

完整版见 [README](../README.md#-项目结构)，这里只列最关键的：

```
AMuBBS/
├── app/           # 应用层：Controllers（17 前台 + 16 后台）/ Services（26）/ Models（40）
├── core/          # 自研微框架（24 个类，含 hooks.php / Event.php / PluginManager.php）
├── config/        # app.php / database.php / cache.php
├── plugins/       # 插件目录（Example 为自带示例）
├── resources/     # 视图（103 个）与多语言
├── public/        # Web 根目录：index.php / .htaccess / assets/ / uploads/
├── storage/       # 运行时：cache / logs / sessions / plugin_config
├── install/       # 安装向导、database.sql（39 张表）、INSTALL.md
└── scripts/       # 验证脚本：smoke + 3 个自检 + 5 个静态检查器
```

## 0.8 开发与验证

一条命令跑完全部验证（推荐）：

```bash
bash scripts/verify.sh          # Linux / macOS / CI
powershell scripts/verify.ps1   # Windows
```

它会依次跑：全量 `php -l` → 7 个静态检查器 → 3 个自检 → 冒烟测试，最后打印汇总并给出退出码。
常用参数：`SKIP_SMOKE=1`（没起服务时跳过冒烟）、`SMOKE_BASE_URL=https://你的域名`（验证线上节点）、
`PHP_BIN=/usr/bin/php8.2`（指定 PHP）。

想单独跑某一步：

```bash
# 1. 语法：全量 php -l
# 2. 静态检查
php scripts/check_imports.php    # 模型的 use 是否漏写/多余
php scripts/check_routes.php     # 每条路由的控制器方法是否存在
php scripts/check_schema.php     # 代码引用的表是否都在安装脚本/运行库里
php scripts/check_layers.php     # Controllers/Services 里有没有偷偷写 SQL
php scripts/check_events.php     # 事件常量有没有「定义了但永不触发」的死钩子
php scripts/check_env.php        # .env.example 与代码读取的配置项是否一致
php scripts/check_docs.php       # 文档代码围栏是否成对、文档内链接是否有效
# 3. 自检（不需要数据库/Redis）
php scripts/selftest_cache.php
php scripts/selftest_hooks.php
php scripts/selftest_install.php
# 4. 冒烟：真实 HTTP，125 项（需要站点已安装、后台验证码关闭）
php scripts/smoke.php
```

**硬性要求：以上验证必须在「无 Redis」环境下全绿**——这正是目标部署环境的形态。
`smoke.php` 与 `selftest_install.php` 都不依赖 Redis；缓存自检还会专门覆盖「没有 Redis 时降级到文件驱动」的分支。

## 0.9 常见问题

| 现象 | 处理 |
| --- | --- |
| 整站白屏 / 500 | 先看 `storage/logs/` 与主机的 PHP 错误日志；本地可临时把 `APP_DEBUG=true`（**生产别开**，会暴露路径） |
| 提示目录不可写 | `storage/`、`public/uploads/` 给写权限（Linux `chmod -R 755`，个别主机需要 777） |
| 改了配置不生效 | 后台「清缓存」，或直接删 `storage/cache/` 下的文件（`.gitkeep` 留着） |
| 搜索没结果 / 慢 | 导入 `install/optional_fulltext.sql`（可选）；中文短词搜索走 LIKE 回退，不依赖 FULLTEXT |
| 后台样式错乱 | 确认 `public/assets/vendor/` 上传完整（layui / layuimini / font-awesome 都是本地文件，不走 CDN；版本见 `public/assets/vendor/VERSIONS.txt`） |
| 自动化脚本登不进后台 | 后台关掉登录验证码（验证码是图形码，脚本过不了） |
| 想确认服务活着 | `GET /health` 返回 `{"status":"ok","timestamp":...}`；数据库不通时返回 500 + `error` |
