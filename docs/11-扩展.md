# 从单机到多机扩展指南

> 本文讲「什么时候需要加机器、加机器要同步什么」。
> - 共享主机 / 单机部署：见 [`install/INSTALL.md`](../install/INSTALL.md)
> - 第二台机器接入的逐条命令：见 [`distributed-deploy.md`](distributed-deploy.md)
> - CDN、负载均衡、主从复制的配置细节：见 [`09-分布式.md`](09-分布式.md)

## 11.1 先认清约束：哪些状态留在本机

AMuBBS 是为「一台机器、一个可写目录」设计的，所以多机部署的第一件事不是改代码，
而是把**本机状态**逐个挪出去。清单如下（每个都能在 `.env` 或部署流程里解决）：

| 状态 | 默认位置 | 多节点方案 |
| --- | --- | --- |
| 缓存 | `storage/cache/`（文件驱动） | `CACHE_DRIVER=redis`，或让每节点各自缓存（能跑，只是命中率低） |
| 会话 | `storage/sessions/`（文件驱动） | **必须** `SESSION_DRIVER=redis`，否则登录态在节点间丢失 |
| 上传文件 | `public/uploads/` | NFS / 主机面板共享目录挂到各节点同一路径（**没有 OSS 等对象存储驱动**） |
| 插件启用状态 | `storage/plugin_config/plugins.json` | 部署时一并同步（或把该目录做成共享目录） |
| 安装锁 | `install/install.lock` | 每个节点都要有，否则会被当成未安装 |
| 日志 | `storage/logs/` | 各节点本地即可；要集中收集见 11.6 |
| 队列 | `queue_jobs` 表 | 天然共享（走数据库），无需额外处理 |
| 页面缓存 | 缓存驱动内 | 文件驱动时是**每节点独立**的：清缓存要么逐台清，要么改用 Redis |

换句话说：**只有会话和上传是「不做就出故障」的**，其余是效率与一致性问题。

## 11.2 阶段一：共享主机 / 单机（0–1000 日活）

一台机器、没有 root、没有 Redis、没有系统 cron 也能跑：

```ini
# .env（真实键名，全部保持默认值即可）
DB_HOST=localhost
DB_DATABASE=你的库名
DB_USERNAME=你的用户名
DB_PASSWORD=你的密码
APP_KEY=用 php -r "echo bin2hex(random_bytes(32));" 生成

CACHE_DRIVER=auto      # 没有 Redis 扩展时自动用文件缓存
SESSION_DRIVER=file    # 会话写 storage/sessions/
CACHE_FILE_GC=200      # 文件缓存惰性 GC
```

保洁与队列靠一次 HTTP 请求触发（在主机面板加个计划任务，命令要能带自定义请求头）：

```bash
curl -fsS -H "X-Cron-Key: <后台设置的 cron_key>" https://你的域名/cron/run
```

特点：零外部服务、成本最低；文件缓存自带惰性 GC，即使**完全不配**定时任务也能正常使用。

## 11.3 阶段二：数据库分离（1000–5000 日活）

Web 与数据库分开，先把 DB 挪走：

1. 在数据库服务器建库建用户，导入 `install/database.sql`；
2. 允许远程连接（`bind-address` + 防火墙只放行 Web 节点内网 IP）；
3. Web 节点 `.env` 把 `DB_HOST` 指向数据库服务器，其余不动。

读多写少时再加**从库**，框架原生支持读连接分离：

```ini
# 多台从库用英文逗号分隔；不配这两项时读连接自动回退主库
DB_READ_HOST=192.168.1.202,192.168.1.203
DB_READ_PORT=3306
```

主从复制的建库/账号/`CHANGE MASTER` 步骤见 [`09-分布式.md`](09-分布式.md) 与
[`distributed-deploy.md`](distributed-deploy.md)。

⚠️ **主从延迟是真实存在的**：写完立刻读的地方（例如刚发完帖就跳详情页）会走读连接，
极端情况下可能读到旧数据。业务上能接受（下一页就正常），但如果你要做「发帖后立即强一致展示」，
要么让该查询显式走主库（`Core\Database::useMaster()` / 事务内），要么别配读从库。

## 11.4 阶段三：多 Web 节点（5000+ 日活）

### 11.4.1 必须改的配置

```ini
SESSION_DRIVER=redis      # 不配这个，用户在两台机器之间会「掉登录」
REDIS_HOST=192.168.1.200  # 缓存/会话共用一套 Redis
REDIS_PORT=6379
REDIS_PASSWORD=改成强密码
CACHE_DRIVER=redis        # 可选：共享缓存，避免各节点缓存不一致
```

### 11.4.2 上传目录共享

```bash
# 存储节点（任选一台，或专用 NAS）
sudo apt install nfs-kernel-server
echo "/data/amubbs/uploads 192.168.1.0/24(rw,sync,no_subtree_check)" | sudo tee -a /etc/exports
sudo exportfs -ra

# 每个 Web 节点
sudo mount -t nfs 192.168.1.200:/data/amubbs/uploads /var/www/amubbs/public/uploads
# 写入 /etc/fstab 以便开机自动挂载
```

### 11.4.3 部署一致性

| 文件/目录 | 怎么办 |
| --- | --- |
| 代码 | 每节点同一版本（`deploy.sh` 或 CI 同步） |
| `.env` | 除 `APP_URL` 外应完全一致（多节点建议统一域名） |
| `storage/plugin_config/plugins.json` | 各节点一致，否则「后台启用了插件但另一台没生效」 |
| `install/install.lock` | 每节点都要有 |
| `storage/cache`、`storage/logs` | 各自独立即可，不要同步 |

### 11.4.4 负载均衡与健康检查

Nginx 侧转发到多个 PHP-FPM / Web 节点即可（配置示例见 `09-分布式.md`）。
每个节点都提供健康检查接口，便于摘除故障节点：

```bash
curl -s https://你的域名/health
# {"status":"ok","timestamp":1790313968}   ← 数据库不通时返回 500 + status=error
```

**定时任务只让一个节点跑**：虽然 `CronSvc` 用带 owner token 的原子锁防并发，
但多节点同时打同一个 URL 属于无谓竞争，建议只在主节点的计划任务里配置。

## 11.5 部署与更新

仓库自带 `deploy.sh`（本机部署 / 远程节点部署）：

```bash
./deploy.sh               # 本机：git pull + 修目录权限 + 重载 PHP-FPM + /health 健康检查
./deploy.sh 192.168.1.102 # 远程节点：rsync 同步后远程执行同样的动作
```

它同步时会**排除** `.env`、`storage/cache/*`、`storage/logs/*`、`public/uploads/*`、
`install/install.lock` —— 这些是「每台机器自己的状态」，不该被覆盖。
注意它**不会**清应用缓存（只重载 PHP-FPM 清 OPcache），所以更新后仍要按下面第 3 步清一次。

手工更新的最小步骤：

1. 上传新代码（不要覆盖 `.env` 与 `storage/`）；
2. 若有数据库变更，先备份再执行 `install/database.sql` 里的新增语句（本项目不做自动迁移）；
3. 清缓存（后台「缓存管理」→ 清全部，或 `find storage/cache -name '*.cache' -delete`——目录是两级分片，`.gitkeep` 保留）；
4. 跑一次 `/cron/run`（带 `X-Cron-Key` 头，重建板块统计、消费队列）；
5. 用冒烟脚本验证，可直接指向任一节点：

```bash
SMOKE_BASE_URL=https://你的域名 php scripts/smoke.php   # 125 项
```

回滚：代码回退到上一版本 → 再清一次缓存。数据库变更的回滚只能用备份，所以**改表之前先备份**。

## 11.6 日志与监控

| 目标 | 做法 |
| --- | --- |
| 单节点排错 | `storage/logs/YYYY-MM-DD.log`（框架审计日志）+ 主机面板里的 PHP 错误日志 |
| 多节点集中 | 每节点 rsync 到一台日志机，或让主机面板/对象存储收集；框架不假设有集中日志服务 |
| 存活监控 | 外部监控每 1–5 分钟打 `/health`，失败告警 |
| 性能 | MySQL 慢查询日志 + `check_layers.php` 保证 SQL 都在 Model 层，便于统一加索引 |

## 11.7 常见问题

| 问题 | 原因与处理 |
| --- | --- |
| 多节点之间会掉登录 | 没配 `SESSION_DRIVER=redis`，会话文件是每节点本地的 |
| 上传后另一台看不到图片 | `public/uploads/` 没做共享挂载 |
| 后台启用了插件，另一台没生效 | `storage/plugin_config/plugins.json` 没同步 |
| 清了缓存还有旧内容 | 文件驱动下缓存是**每节点独立**的：要么逐台清，要么改用 Redis |
| 定时任务跑重复了 | `CronSvc` 有原子锁会跳过并发，但建议只让一个节点触发 |
| 刚发完帖详情页看不到自己的回复 | 配了读从库且有主从延迟，见 11.3 的说明 |
| 想用对象存储放附件 | **未实现**：上传固定落 `public/uploads/`，多机请用共享挂载 |

---

**一句话总结**：能上共享主机就先上共享主机（零依赖、零运维）；
要扩容时，先把**会话**和**上传**挪成共享的，其余状态按表逐项处理即可。
