# 插件开发指南

> 面向插件作者。系统实现细节见 [`08-插件系统.md`](08-插件系统.md)。
> 本文里的每一条 API 都在当前代码里存在，并已用 `scripts/selftest_hooks.php`（61 项）与真实 HTTP 探针验证过。

## 10.1 5 分钟写一个插件

```
plugins/HelloWorld/
├── plugin.json     # 元数据（必须）
└── Plugin.php      # 主类，实现 Core\PluginInterface（必须）
```

`plugins/HelloWorld/plugin.json`：

```json
{
    "name": "helloworld",
    "title": "Hello World",
    "version": "1.0.0",
    "description": "发帖标题自动加后缀，注册时记一条日志",
    "author": "你的名字",
    "entry": "Plugin.php",
    "class": "Plugins\\HelloWorld\\Plugin"
}
```

`plugins/HelloWorld/Plugin.php`：

```php
<?php

namespace Plugins\HelloWorld;

use Core\PluginInterface;

class Plugin implements PluginInterface
{
    public function register(): void
    {
        // 过滤器：改标题（值在前，附加参数在后）
        add_filter('thread.title', function (string $title, int $forumId): string {
            return $title . ' [HelloWorld]';
        }, 10);

        // 动作：新用户注册（载荷是一个关联数组）
        add_action('user.registered', function (array $data) {
            error_log('[HelloWorld] 新用户: ' . ($data['username'] ?? '?'));
        }, 10);
    }
}
```

上传目录后，到后台 **系统管理 → 插件管理** 点「启用」即可。
不需要 Composer、不需要改任何核心文件、不需要重启任何进程。

## 10.2 目录结构与 `plugin.json`

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 否 | 目录名 | 插件唯一标识（状态文件里的键、后台操作用的参数）；建议全小写、无空格 |
| `title` | 否 | `name` | 后台显示名 |
| `version` | 否 | `1.0.0` | 版本号，仅展示 |
| `description` | 否 | 空 | 后台列表里的说明 |
| `author` | 否 | 空 | 后台列表里的作者 |
| `entry` | 否 | `Plugin.php` | 入口文件名（相对插件目录） |
| `class` | 否 | `Plugins\{目录名转大驼峰}\Plugin` | 插件主类全名 |

约定：

- 一个插件 = `plugins/` 下的一个目录，目录名建议与 `name` 一致（`plugins/HelloWorld`）。
- 自动加载只映射了 `Plugins\` → `plugins/`，**插件自己不需要写 autoloader**；
  `Plugins\HelloWorld\Plugin` 会解析到 `plugins/HelloWorld/Plugin.php`。
- 想带自己的子类，就放在同一个命名空间下，例如 `Plugins\HelloWorld\Helper` → `plugins/HelloWorld/Helper.php`。
- 静态资源放在 `assets/` 子目录（见 10.5.5）。

## 10.3 插件契约与生命周期

```php
namespace Core;

interface PluginInterface
{
    /** 注册钩子：插件启用后，每次请求都会调用一次（含后台、API、CLI 脚本） */
    public function register(): void;
}
```

可选生命周期（**不实现也不会报错**）：

```php
public function install(): void;    // 首次启用时调用一次（建表、写默认设置）
public function uninstall(): void;  // 后台点「卸载」时调用（清理数据）
```

| 时机 | 行为 |
| --- | --- |
| 首次启用 | 写状态文件后调用一次 `install()` |
| 停用后再启用 | `installed_at` 已存在，**不会**再调用 `install()` |
| 卸载 | 调用 `uninstall()`，然后清除启用状态（插件文件保留，可再次启用） |
| `register()` 抛异常 | 只记日志，其它插件照常运行（本站不会白屏） |
| `install()` 抛异常 | 只记日志，插件仍保持启用状态；后台操作不会 500 |

`register()` 每次请求都会被调用，所以它必须**只做挂钩子**这种极轻的工作：
不要在 `register()` 里查库、发邮件、写文件。

## 10.4 钩子速查

### 10.4.1 全局函数

```php
add_action(string $tag, callable $callback, int $priority = 10): void
do_action(string $tag, ...$args): void
add_filter(string $tag, callable $callback, int $priority = 10): void
apply_filters(string $tag, mixed $value, ...$args): mixed
remove_action(string $tag, ?callable $callback = null, ?int $priority = null): void
remove_filter(string $tag, ?callable $callback = null, ?int $priority = null): void
has_action(string $tag): bool
has_filter(string $tag): bool
```

- **优先级**数字越小越先执行；核心自带监听器在优先级 `0`，插件默认 `10`。
  想比核心监听器先跑，就传 `0` 或负数。
- **Action 回调返回 `false` 会中断后续回调**（不是 WordPress 的行为，是本项目保留的旧语义），
  除非有意拦截，否则不要 `return false`。
- **Filter** 必须返回（修改后的）值；忘了 `return` 会把下游的值变成 `null`。
- `remove_action('tag')`（不传回调）清空该 tag 的全部回调。

### 10.4.2 事件载荷的形状（重要）

核心业务代码是用 `Event::dispatch(Events::X, [...])` 触发事件的，
它等价于 `do_action('x', [...])`，也就是**整个数组作为第一个参数**：

```php
add_action('thread.created', function (array $data) {
    $threadId = (int)$data['thread_id'];
    // ...
});
```

写 `function ($threadId)` 会收到一个数组，这是最常见的踩坑点。

### 10.4.3 可用事件

`App\Events\Events` 里定义的常量值就是钩子名（可以直接监听，也可以自己写字符串）。
**30 个常量全部会触发**（`php scripts/check_events.php` 会守住这一点，防止再出现「定义了但永不触发」的死钩子）：

| 钩子名 | 载荷 | 时机 |
| --- | --- | --- |
| `user.registered` | `user_id, username, ip` | 注册成功 |
| `user.logged_in` | `user_id, username, ip` | 登录成功 |
| `user.logged_out` | `user_id, username` | 退出登录 |
| `user.password_reset` | `user_id, action, ip` | 密码重置成功 |
| `thread.created` | `thread_id, forum_id, user_id, username` | 发帖成功（事务提交后） |
| `thread.updated` | `thread_id, user_id` | 编辑帖子成功 |
| `thread.deleted` | `thread_id, user_id` | 删除帖子成功 |
| `post.created` | `post_id, thread_id, user_id, username` | 回帖成功 |
| `post.updated` | `post_id, thread_id, user_id, author_id` | **作者本人**编辑自己的回复 |
| `post.deleted` | `post_id, thread_id, user_id, author_id` | **作者本人**删除自己的回复 |
| `mod.thread.locked` | `thread_id, forum_id, is_locked, user_id` | 版主/管理员锁定或解锁帖子 |
| `mod.thread.moved` | `thread_id, from_forum_id, to_forum_id, user_id` | 版主/管理员移动帖子到别的板块 |
| `mod.post.edited` | `post_id, thread_id, user_id, author_id` | **版主/管理员**编辑别人的回复 |
| `mod.post.deleted` | `post_id, thread_id, user_id, author_id` | **版主/管理员**删除别人的回复 |
| `admin.user.updated` | `action, admin_id, detail, target_type, target_id` | 后台所有用户变更（13 处） |
| `admin.user.deleted` | 同上 | 后台删除用户 |
| `admin.forum.created` | 同上 | 后台新建板块 |
| `admin.forum.updated` | 同上 | 后台编辑板块 |
| `admin.forum.deleted` | 同上 | 后台删除板块 |
| `admin.thread.deleted` | 同上 | 后台删帖/删回帖/删附件 |
| `admin.thread.topped` | 同上 | 后台置顶/取消置顶 |
| `admin.thread.highlighted` | 同上 | 后台加精/取消加精 |
| `admin.settings.saved` | 同上 | 后台保存设置 |
| `admin.ip.blocked` | 同上 | 后台封禁 IP |
| `admin.ip.unblocked` | 同上 | 后台解封 IP |
| `admin.sensitive_word.added` | 同上 | 后台添加敏感词 |
| `admin.cache.cleared` | 同上 | 后台清缓存 |
| `admin.cluster.node_created` | 同上 | 后台添加集群节点 |
| `admin.cluster.node_toggled` | 同上 | 后台启停/编辑集群节点 |
| `admin.cluster.node_deleted` | 同上 | 后台删除集群节点 |

`admin.*` 载荷是审计日志形状：

```php
['action' => '删除帖子', 'admin_id' => 1, 'detail' => '删除帖子 ID:12', 'target_type' => 'thread', 'target_id' => 12]
```

另外还有一个**框架级钩子**（不在 `Events` 常量里，无参数）：

| 钩子名 | 载荷 | 时机 |
| --- | --- | --- |
| `app.booted` | 无 | 应用就绪、路由分发前，每个请求一次 |

```php
// 适合做「每请求一次」的轻量初始化，不要在这里做重活
add_action('app.booted', function () {
    // ...
});
```

#### 编辑 / 删除回复：作者与版主是两个不同的钩子

回复的编辑与删除都允许「作者本人」和「版主/管理员」两种身份，但核心**只触发其中一条**，不会两条都发：

| 谁在操作 | 触发哪个 |
| --- | --- |
| 作者本人编辑自己的回复 | `post.updated` |
| 版主/管理员编辑别人的回复 | `mod.post.edited` |
| 作者本人删除自己的回复 | `post.deleted` |
| 版主/管理员删除别人的回复 | `mod.post.deleted` |

载荷里 `user_id` 是**执行操作的人**，`author_id` 是**回复作者**（判断「是不是版主在管别人」用这两个比一下即可）。
之所以互斥，是为了让「扣分 / 发通知」这类插件不会因为一次操作被触发两次。

### 10.4.4 可用过滤器

| 钩子名 | 值 | 附加参数 | 说明 |
| --- | --- | --- | --- |
| `thread.title` | 标题字符串 | `$forumId` | 发帖写库前，改了就按改后的存 |
| `post.content` | 内容字符串 | `$forumId` | 同上 |

```php
// 给特定板块的标题加前缀
add_filter('thread.title', function (string $title, int $forumId): string {
    return $forumId === 1 ? '[公告] ' . $title : $title;
}, 10);
```

过滤器在事务开启**之前**执行，所以插件在这里改出来的内容会和正常发帖一样落库。

## 10.5 常用能力

### 10.5.1 数据库

推荐用 `App\Models\*`（模型自带 SQL 与缓存失效），例如：

```php
use App\Models\Thread;

$thread = Thread::find($threadId);
```

确实需要自己写 SQL 时用 `Core\Database`（插件不受后台分层检查约束，但仍建议优先用模型）：

```php
use Core\Database;

$rows = Database::fetchAll('SELECT id, title FROM threads WHERE forum_id = ? LIMIT 5', [$forumId]);
$one  = Database::fetchOne('SELECT COUNT(*) AS c FROM posts WHERE thread_id = ?', [$threadId]);
Database::execute('UPDATE threads SET views = views + 1 WHERE id = ?', [$threadId]);
```

写多张表要保证一致性时，用 `Database::transaction(function () { ... })` 或
`beginTransaction() / commit() / rollBack()`。

### 10.5.2 缓存（无 Redis 也能用）

```php
use Core\Cache;

Cache::set('myplugin:top', $value, 600);                        // 写
$value = Cache::get('myplugin:top');                            // 读，未命中返回 null
$value = Cache::get('myplugin:top', fn() => expensive(), 600);  // 读不到就回调重建
Cache::delete('myplugin:top');
```

缓存驱动由 `config/cache.php` 决定；没有 Redis 时自动降级为文件缓存，插件代码不用改。
缓存键请加自己的前缀（如 `myplugin:`），避免和核心键冲突。

### 10.5.3 设置项

```php
use App\Services\SettingSvc;

$size = SettingSvc::getInt('myplugin_size', 20);            // 读（带整型转换）
$on   = SettingSvc::getBool('myplugin_enabled', true);      // 读布尔
SettingSvc::setMany(['myplugin_size' => '30']);             // 写（已存在则覆盖）
$mine = SettingSvc::allWithPrefix('myplugin_');             // 按前缀批量读
```

写入后缓存会自动失效。设置项键名同样建议加插件前缀。

### 10.5.4 输出内容

插件没有专用的视图解析器，两种做法：

```php
// 1) 直接输出
echo '<div class="alert alert-info">' . htmlspecialchars($text, ENT_QUOTES, 'UTF-8') . '</div>';

// 2) 用插件自己的模板文件
$tpl = APP_PATH . 'plugins/HelloWorld/views/box.php';
if (is_file($tpl)) {
    include $tpl;   // 模板里可以用 $text 等局部变量
}
```

注意：拼 HTML 一定要转义。

### 10.5.5 静态资源

放在 `plugins/HelloWorld/assets/`，通过路由访问：

```
/plugin-assets/HelloWorld/logo.png
/plugin-assets/HelloWorld/css/style.css
/plugin-assets/HelloWorld/js/app.js
```

规则：插件名只能是字母数字下划线连字符；文件路径含 `..` 会被拒；
扩展名限 `png jpg jpeg gif webp svg css js woff woff2 ttf eot map json ico`（**`.php` 访问不到**）；
响应带 ETag 与 30 天强缓存。

### 10.5.6 自己的数据表

插件要建表时，建议把 SQL 放进插件目录的 `sql/install.sql`，在 `install()` 里执行：
`install()` 只在**首次启用**时跑一次，正是建表的时机。
（这是可选的：不想动数据库的插件可以不建表。）

## 10.6 启用、停用、卸载（无 shell 环境）

1. 把插件目录上传到 `plugins/`（FTP / 主机面板文件管理器都行）。
2. 后台 **系统管理 → 插件管理** → 找到插件 → 点「启用」。
3. 状态写入 `storage/plugin_config/plugins.json`，**从下一个请求开始生效**
   （当前这次请求的钩子已经注册完了，页面上的提示也这么写）。
4. 「停用」只把 `enabled` 置为 false，`installed_at` 保留，因此再次启用不会重复建表。
5. 「卸载」会调用 `uninstall()` 并清除状态，但**不会删你的插件文件**；
   彻底删除要先在后台卸载，再用 FTP 删目录。

手工启停（不给 shell 时的应急办法）：直接编辑 `storage/plugin_config/plugins.json`：

```json
{ "helloworld": { "enabled": true, "installed_at": 1790313968 } }
```

## 10.7 调试与排错

| 手段 | 说明 |
| --- | --- |
| `error_log('[MyPlugin] ...')` | 写 PHP 错误日志；开发时 `php -S` 会直接打在终端上 |
| `storage/logs/YYYY-MM-DD.log` | 这是**框架的操作日志**（由 `LogListener` 写后台/版主动作），插件日志不会自动进这里 |
| 后台「插件管理」的「本次请求已加载」徽章 | 确认插件这次请求真的被加载了 |
| `has_action('thread.created')` | 在插件里自查是否挂上（返回 bool） |
| `Event::didAction('thread.created')` | 这个 tag 本次请求触发过几次（调试用） |
| 后台清缓存 | 缓存相关的怪现象先清一次缓存再判断 |

常见问题：

| 现象 | 原因 |
| --- | --- |
| 后台看不到插件 | 目录不在 `plugins/` 下，或 `plugin.json` 缺失/JSON 语法错误（会记日志） |
| 启用了但回调不触发 | 钩子名拼错；或事件本身当前不会派发（见 10.4.3 的 6 个）；或 `register()` 里抛了异常（看错误日志） |
| 回调收到的是数组而不是字符串 | action 的载荷就是关联数组，签名写 `function (array $data)` |
| 过滤器改完值变成 null | 回调里忘了 `return` |
| 启用后站点 500 | 检查 `register()` 是否在请求早期做了查库/重活；错一个插件不会影响别的插件，但仍会污染它自己注册的钩子 |

## 10.8 完整示例：发帖自动加前缀

需求：在板块 2 发帖时标题自动补 `[问答] `，并在错误日志里记录发帖人。

`plugins/AutoTag/plugin.json`：

```json
{
    "name": "autotag",
    "title": "发帖自动加前缀",
    "version": "1.0.0",
    "description": "在指定板块发帖时自动给标题加前缀",
    "entry": "Plugin.php",
    "class": "Plugins\\AutoTag\\Plugin"
}
```

`plugins/AutoTag/Plugin.php`：

```php
<?php

namespace Plugins\AutoTag;

use App\Services\SettingSvc;
use Core\PluginInterface;

class Plugin implements PluginInterface
{
    /** 要加前缀的板块 */
    private const FORUM_ID = 2;
    private const PREFIX   = '[问答] ';

    public function register(): void
    {
        // 首次安装写下的开关，关掉就什么都不做
        if (!SettingSvc::getBool('autotag_enabled', true)) {
            return;
        }

        add_filter('thread.title', [$this, 'prefixTitle'], 20);

        add_action('thread.created', function (array $data) {
            error_log(sprintf(
                '[AutoTag] 新帖 #%d 板块 %d 作者 %s',
                (int)($data['thread_id'] ?? 0),
                (int)($data['forum_id'] ?? 0),
                (string)($data['username'] ?? '?')
            ));
        }, 10);
    }

    public function prefixTitle(string $title, int $forumId = 0): string
    {
        if ($forumId !== self::FORUM_ID || str_starts_with($title, self::PREFIX)) {
            return $title;
        }

        return self::PREFIX . $title;
    }

    public function install(): void
    {
        SettingSvc::setMany(['autotag_enabled' => '1']);
    }

    public function uninstall(): void
    {
        // 清掉自己写过的设置项，别给站点留垃圾
        SettingSvc::setMany(['autotag_enabled' => '0']);
    }
}
```

要点回顾：钩子用 `add_filter('thread.title', ...)` 改值、用 `add_action('thread.created', ...)` 记日志；
`install()` 只在首次启用时跑；回调都保持极轻。

## 10.9 发布检查清单

- [ ] `plugin.json` 的 `name` / `class` / `entry` 与实际目录、类名一致（`class` 不写会按目录名推断，写错会静默不加载）。
- [ ] 主类实现 `Core\PluginInterface`，`register()` 只挂钩子、不做重活。
- [ ] 钩子名与载荷键名对照 `docs/08-插件系统.md` 的表格，没有使用「已定义但未派发」的 6 个事件。
- [ ] 所有过滤器回调都有 `return`，且类型与传入值兼容（否则下游会拿到 `null`）。
- [ ] 数据表/设置项/缓存键都带插件前缀；卸载时清理干净。
- [ ] 输出 HTML 全部转义；不要直接回显用户输入。
- [ ] 在**无 Redis** 环境下跑过一次：`php scripts/smoke.php` 全绿。
- [ ] 停用插件后站点一切照旧（回调不依赖插件自身的临时状态）。
