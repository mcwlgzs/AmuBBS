# 后台管理系统

> 本文描述当前后台的**真实实现**。早期版本这里是「Layui + 分布式配置面板」的设计稿
> （含 `Admin\Controllers` 命名空间、`admin/route/cluster.php`、插件市场、在线用户监控等），
> 那些内容与代码不符，已整体替换。中间还短暂用过 Tabler 1.5 + htmx 的局部替换方案，也已下线。
> 现在后台是 **layuimini v2（Layui 2.6.3）+ iframe 多标签外壳**，前台则是 htmx 2 + 自研 CSS（不加载 layui）。

## 12.1 技术栈与整体结构

| 项 | 现状 |
| --- | --- |
| UI 框架 | **layuimini v2 + Layui 2.6.3**（`public/assets/vendor/layuimini`、`public/assets/vendor/layui`） |
| 图标 | Font Awesome 4.7（`public/assets/vendor/font-awesome`，layuimini 自带的图标体系；菜单项写 `fa fa-*`） |
| 交互 | **Layui 模块**：`table.render` 取数、`layer` 弹层与确认、`form`、`element`，无前端构建步骤 |
| 外壳 | **iframe 多标签**：`miniAdmin` + `miniMenu`（无限级左侧菜单）+ `miniTab`（可关闭的多 tab，上限 20 个） |
| 主题 | layuimini 自带 5 套配色（顶栏「配色方案」按钮）；`bgColorDefault: false` 表示沿用用户上次的选择 |
| 覆写样式 | `public/assets/css/admin-layui.css`——本项目在 layui / layuimini 之上的一点补充（`.admin-muted`、`.admin-tag-*`、`.admin-notice*` 等） |
| 版本 | 见 `public/assets/vendor/VERSIONS.txt`（layui 2.6.3、layuimini 2.0.4、Font Awesome 4.7） |

资源加载顺序（改布局时别弄反）——外壳和子页面是两份模板，引的东西不一样：

```
外壳 /admin（resources/views/admin/layout.php）
<head>
  <link href="vendor/layui/css/layui.css">                  ← layui 基础样式
  <link href="vendor/layuimini/css/layuimini.css">           ← 外壳样式（顶栏 / 菜单 / tab）
  <link href="vendor/layuimini/css/themes/default.css">
  <link href="vendor/font-awesome/css/font-awesome.min.css">
  <link href="assets/css/admin-layui.css">                   ← 覆写放在最后
  <style id="layuimini-bg-color">                           ← 留给 layuimini 写配色 CSS 变量
<body class="layui-layout-body layuimini-all">
  <script src="vendor/layui/layui.js">
  <script src="vendor/layuimini/js/lay-config.js">           ← 必须在 layui.js 之后：
                                                               它用 document.scripts 最后一项算 rootPath，
                                                               再 layui.config({base}) 把 lay-module/ 注册给 layui.extend()
  <script> layui.use(['jquery', 'layer', 'miniAdmin'], …) </script>

子页面（resources/views/admin/layout_child.php，每个 iframe 一份）
<head>
  <link href="vendor/layui/css/layui.css">
  <link href="vendor/font-awesome/css/font-awesome.min.css">
  <link href="vendor/layuimini/css/public.css">              ← 页面级样式；子页面**不**引 layuimini.css / lay-config.js
  <link href="assets/css/admin-layui.css">
<body>
  <script src="vendor/layui/layui.js">                       ← 必须早于页面内联脚本
  <script src="assets/js/admin-layui.js">                    ← AdminUi：CSRF 头 + 提示 + 确认 + 刷新外层表格
  <div class="layuimini-container"><div class="layuimini-main"> …正文… </div></div>
```

⚠️ 子页面里 `layui.js` 放在 `<head>` 之后的 `body` 开头、而不是 `body` 末尾：页面片段里的
`layui.use([...])` 会先于 `body` 末尾的脚本执行，放末尾的话 `layui` 还没定义，表格/表单全都初始化不了。

## 12.2 渲染模型：外壳 + iframe 子页面

后台是 layuimini 的经典「iframe 多 tab」形态，一套代码两种输出：

| 请求 | 渲染的模板 | 输出 |
| --- | --- | --- |
| `GET /admin` | `resources/views/admin/layout.php` | 外壳：顶栏 + 左侧菜单 + tab 容器。**只有这一条路由**渲染外壳 |
| 其它 `/admin/*` | `resources/views/admin/layout_child.php` | **一个完整 HTML 文档**，在外壳的 iframe 里打开 |

所有子页面都走 `AdminBase::renderAdmin($view, $data, $currentPage)`：它先 `ob_start()` 把视图缓冲成
`$content`，再套 `admin/layout_child` 输出完整文档。**没有按 `HX-Request` 返回片段的分支**——
直接访问 URL、刷新、在新标签页打开都必须能独立渲染（`scripts/smoke.php` 有断言守着，防止片段模式被加回来）。
`$data['pageTitle']` 没给时会去 `config/admin_nav.php` 里按 `$currentPage` 取，菜单与标题同一个数据源。

外壳结构（`layout.php`）：

```
<body class="layui-layout-body layuimini-all">
  <div class="layui-layout layui-layout-admin">
    <div class="layui-header header">              顶栏：logo（menu.json 的 logoInfo）+ 折叠/全屏/刷新/账号/配色
    <div class="layui-side layuimini-menu-left">   左侧无限级菜单树（miniMenu 渲染）
    <div class="layuimini-loader">                 初始化加载层
    <div class="layui-body">
      <div class="layuimini-tab layui-tab" lay-filter="layuiminiTab">
        <ul class="layui-tab-title">               可关闭的 tab 列表
        <div class="layui-tab-content">
          <div id="layuiminiHomeTabIframe">        首页 tab：miniAdmin 往这里塞 iframe
```

外壳只在 `/admin` 里初始化一次：

```js
layui.use(['jquery', 'layer', 'miniAdmin'], function () {
  layui.miniAdmin.render({
    iniUrl: '/admin/menu.json',   // 菜单 / 首页 / logo 全部由这个接口提供
    urlHashLocation: true,        // tab 与 URL hash 同步，刷新后能回到原 tab
    bgColorDefault: false,        // 主题配色：沿用用户上次选择
    multiModule: false,           // 单模块：7 个一级分组全部收进左侧菜单树，不占用顶栏
    menuChildOpen: false,         // 分组默认收起，只有当前页面所在分组自动展开
    loadingTime: 0,
    pageAnim: true,               // iframe 淡入动画
    maxTabNum: 20                 // 最多同时开 20 个 tab
  });
});
```

刷新子页面不会重建外壳，切换 tab 也不会重新请求已经打开过的页面——这正是当初从
「Tabler 1.5 + htmx 局部替换」换回 iframe 形态换来的东西，取舍见 [`06-前端选型.md`](06-前端选型.md)。

## 12.3 菜单与模块清单

菜单定义在 `config/admin_nav.php`（`groups` → 页面 key → `title` / `href` / `icon`），它是菜单与页面标题的**唯一数据源**：
`DashboardController::menu()` 把它转成 layuimini 的 `{homeInfo, logoInfo, menuInfo}` 由 `/admin/menu.json` 输出给外壳，
`AdminBase::renderAdmin()` 也用它按页面 key 取子页面 `<title>`。页面 key 与 `renderAdmin()` 的第三个参数一致。

| 分组 | 页面（26 个） |
| --- | --- |
| 总览 | 仪表盘 `/admin/dashboard`、监控统计 `/admin/monitor` |
| 内容管理 | 板块管理 `/admin/forums`、帖子管理 `/admin/threads`、回帖管理 `/admin/posts`、附件管理 `/admin/attachments` |
| 运营管理 | 公告管理 `/admin/announcements`、标签分类 `/admin/tag-categories`、敏感词 `/admin/sensitive-words`、友情链接 `/admin/friend-links`、导航管理 `/admin/navigation` |
| 用户管理 | 用户列表 `/admin/users`、用户组 `/admin/user-groups`、等级设置 `/admin/levels`、用户设置 `/admin/user-settings`、会员设置 `/admin/vip-settings` |
| 互动管理 | 通知管理 `/admin/notifications`、私信监控 `/admin/messages`、积分记录 `/admin/credit-logs` |
| 系统管理 | 系统设置 `/admin/settings`、系统信息 `/admin/system-info`、缓存管理 `/admin/cache`、**插件管理 `/admin/plugins`**、集群管理 `/admin/cluster` |
| 安全管理 | IP 黑名单 `/admin/ip-blacklist`、操作日志 `/admin/logs` |

另外有 **16 个 JSON 表格接口** `/admin/api/{forums,threads,posts,users,attachments,announcements,sensitive-words,tag-categories,notifications,messages,ip-blacklist,friend-links,logs,credit-logs,levels,user-groups}`，
返回 `{code,msg,data,count}`。这**正是 layui `table.render` 的数据协议**，后台所有列表页都靠它取数
（`AdminBase::jsonTable()`），所以返回结构不能改；顶栏通知角标也读 `/admin/api/notifications`。

## 12.4 权限：两层认证

`App\Middlewares\AdminAuth` 是所有后台路由（`/admin/*`）的守卫，两层加一道可选白名单：

1. **会话身份**：`$_SESSION['group_id']` 必须等于 `PermissionSvc::ADMIN_GROUP_ID`（管理员组 id = 3）。
2. **IP 白名单**（可选）：后台设置 `admin_bind_ip` 填了 IP 列表时，非白名单 IP 直接拒绝。
3. **AdminToken**（`Core\AdminToken`）：第二层令牌校验，令牌用 `APP_KEY` 做 HMAC 签名。
   没有令牌 / 令牌失效时按 `AdminToken::verify()` 返回的原因区分处理（重新登录 or 拒绝）。

被拒时：普通请求跳登录页，AJAX / JSON 请求返回 401 JSON，不会返回一个「看似正常」的后台页面。

> 后台账号就是普通用户账号，只是用户组是管理员组；「删除用户 / 改用户组」这类操作
> 都能把自己锁在门外，所以相关页面把当前登录者排除在批量操作之外。

## 12.5 交互约定（Layui / AdminUi）

### 12.5.1 变更统一走 `respondMutation()`

```php
public function tagCategoryCreate(): void
{
    $this->requireAdmin();
    // ... 取参、校验 ...
    TagCategory::createCategory($name, $forumId, $sortOrder);

    $this->respondMutation(true, "已添加分类「{$name}」", fn() => $this->renderTagCategoriesPage());
}
```

- **后台实际走的路径**：`AdminUi.post()`（`public/assets/js/admin-layui.js`）用 jQuery `$.post` 发
  `X-Requested-With: XMLHttpRequest`，`isHtmx()` 因此为 `false`，服务端返回 `{code,msg}` JSON；
  前端读到 `code === 0` 就 `layer.msg` 弹提示，再由回调 `table.reload()` / `closeLayerAndReload()` 刷新列表。
- **遗留分支**：仍带 `HX-Request` 头的外部调用方会拿到 `HX-Trigger: adminFlash` + 重渲染后的片段。
  `AdminBase::htmxFlash()` 保留只为兼容它们——后台自己的视图里**已经没有任何 `hx-*` 属性**，
  也没有视图监听 `adminFlash`。

⚠️ 那个遗留分支里 `adminFlash` 的中文必须经 `json_encode` 转成 `\uXXXX`：**HTTP 头按 ISO-8859-1 逐字节解码**，
直接把 UTF-8 中文塞进响应头，浏览器读到的是乱码。`AdminBase::htmxFlash()` 已经处理了这一点。

### 12.5.2 CSRF

- 外壳与每个子页面的 `<head>` 里都有 `<meta name="csrf-token" content="…">`（`Csrf::tokenMeta()` 输出，每会话一个 token）。
- `Csrf` 中间件接受 `_csrf_token` 表单字段或 `X-CSRF-TOKEN` 请求头；GET/HEAD/OPTIONS 不校验。
- `admin-layui.js` 加载时用 `layui.jquery.ajaxSetup()` 给所有 AJAX 统一加上 `X-CSRF-TOKEN` 与
  `X-Requested-With`；layui 的 `table` / `form` 内部也走 `$.ajax`，所以设置一次就够，视图里不用手写 token。

### 12.5.3 表单与确认

- 删除这类破坏性操作一律走 `AdminUi.confirmPost(text, url, data, onSuccess)`（内部是 `layer.confirm`），
  避免误点；不要用 `hx-confirm`——后台已经没有 htmx 属性了。
- 批量操作勾 `layui table` 的 checkbox（`table.checkStatus()` 收 id），再由 `AdminUi.post()` 提交，不用 `hx-include`。
- 表单弹层由 `layer.open({type: 2, content: '…/form?id=N'})` 打开（内容仍是 `layout_child` 渲染的完整子页面），
  保存成功后调 `AdminUi.closeLayerAndReload(tableId)`：关掉自己 + 重载外层列表。
- 控件用 layui 体系（`layui-input` / `layui-form-select` / `layui-btn layui-btn-sm`），
  辅助说明文字用 `.admin-muted`，长文本截断用 `.admin-ellipsis`（定义在 `public/assets/css/admin-layui.css`）。
- 表单类公共片段放在 `resources/views/admin/partials/`（`group_form.php`、`level_form.php`、
  `announcement_form.php`、`forum_form.php`、`nav_link_form.php`、`cluster_form.php` …）。

### 12.5.4 空状态

- 表格页：用 `table.render({ text: { none: '暂无××，点上方「新增」创建' } })` 覆盖默认提示，
  把「怎么产生第一条数据」写进去（见 `resources/views/admin/tag_categories.php`、`navigation.php`）。
- 非表格页（如 `resources/views/admin/monitor.php` 的几个榜单）：空态文案配一行 `.admin-muted` 说明，
  不要只输出一行灰字「暂无数据」——那看不出是「空」还是「没加载」。

## 12.6 各功能页的边界（容易误解的地方）

### 12.6.1 集群管理 `/admin/cluster`

管理 `cluster_nodes` 表的**节点清单**：类型（MySQL / Redis）、名称、主机、端口、权重、附加配置，
支持新增/编辑/启停/删除，以及**连通性测试**（`/admin/cluster/test`，结果按节点缓存，避免每次点都连一次）。

⚠️ 它**不负责把流量路由到这些节点**：
真正的读写分离由 `.env` 的 `DB_READ_HOST` 决定，缓存/会话走 `CACHE_DRIVER` / `SESSION_DRIVER`。
这个页面的定位是「多机部署的登记与巡检面板」，配置改完仍要落 `.env` 并重启 PHP-FPM。
（这也解释了 `check_layers.php` 里为什么给 `SystemController` 开了唯一一个数据访问例外：
连通性测试连的是远端主机，而框架连接绑定的是本机配置。）

### 12.6.2 缓存管理 `/admin/cache`

按类型清缓存（页面/数据/全部），并展示缓存概况。文件驱动下等价于删 `storage/cache/` 里两级分片目录中的 `*.cache` 文件
（`find storage/cache -name '*.cache' -delete`）；Redis 驱动下走 `Cache::flush()` / `deletePattern()`。

### 12.6.3 插件管理 `/admin/plugins`

列表 + 启用 / 停用 / 卸载三个按钮（都由 `AdminUi` 发 AJAX，走 `respondMutation()` 的 JSON 分支），状态写 `storage/plugin_config/plugins.json`。
细节见 [`08-插件系统.md`](08-插件系统.md)。

### 12.6.4 操作日志 `/admin/logs`

两个来源，别混：

| 来源 | 位置 | 写入者 |
| --- | --- | --- |
| 审计日志（表格） | `logs` 表 | `LogService`（后台变更、版主操作） |
| 文件日志 | `storage/logs/YYYY-MM-DD.log` | `LogListener`（监听 `admin.*` / `mod.*` 事件） |

后台页面对这两者都有展示/清理入口；`CronSvc` 的 `clean_old_logs` 会清理 90 天前的数据。

## 12.7 新增一个后台页面（照抄这份清单）

1. **控制器**：`app/Controllers/Admin/XxxController.php` extends `AdminBase`；写操作前调 `$this->requireAdmin()`。
   （如果列表数据来自模型，直接调模型静态方法；Controllers/Services 里写 SQL 会被 `check_layers.php` 拦下。）
2. **路由**：在 `core/Bootstrap.php` 的后台段注册，记得带 `[$adminAuth]`：
   ```php
   $this->router->get('/admin/xxx',  ['App\Controllers\Admin\XxxController', 'xxx'], [$adminAuth]);
   $this->router->post('/admin/xxx/create', ['App\Controllers\Admin\XxxController', 'xxxCreate'], [$adminAuth]);
   ```
3. **视图**：`resources/views/admin/xxx.php`，形制照 `forums.php`（列表页参考实现）——
   `<script type="text/html" id="xxxToolbar">` 放顶部工具栏、`<script type="text/html" id="xxxRowBar">` 放行内操作（用 `lay-event` 派发），
   `<table class="layui-hide" id="xxxTable" lay-filter="xxxTable">` 作表格占位，再 `layui.use(['table', 'layer', 'util'])`。
4. **渲染**：`$this->renderAdmin('admin/xxx', $data, 'xxx')`，第三个参数是页面 key，用来从
   `config/admin_nav.php` 取 `<title>`；输出的是 `layout_child` 套出来的完整文档。
5. **菜单**：在 `config/admin_nav.php` 的对应分组里加一项（`title` / `href` / `icon`，图标用 Font Awesome 4.7 类名）。
   **不用动 `layout.php`**——外壳的菜单完全由 `/admin/menu.json` 驱动。
6. **变更响应**：用 `respondMutation($ok, $msg, fn() => $this->renderXxxPage())`，不要自己拼响应头；
   前端统一由 `AdminUi` 弹提示并刷新表格。
7. **验证**：
   - `php scripts/check_routes.php`（路由指向的方法必须存在）；
   - 把路径加进 `scripts/smoke.php` 的 `$adminPages`，冒烟会检查「200 + `<!DOCTYPE` + `layuimini-container` + `vendor/layui/layui.js`，且**不带**外壳标记 `layuimini-menu-left`」；
   - 子页面始终是完整文档，不要按 `HX-Request` 返回片段（smoke 有断言守着）。
