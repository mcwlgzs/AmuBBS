# AMuBBS - 轻量化论坛系统开发文档

## 1. 项目概述

### 1.1 项目定位
AMuBBS 是一个现代化的轻量级论坛系统，专注于**极致性能**和**快速响应**，目标实现毫秒级页面加载速度。

**核心特点：**
- ⚡ **极致性能**：首页 < 50ms，帖子详情 < 100ms
- 🎯 **轻量设计**：精简架构，避免过度工程化
- 🔌 **插件机制**：灵活扩展，核心功能模块化
- 🚀 **快速迭代**：MVP 优先，持续优化

### 1.2 技术选型

| 技术层 | 选型 | 理由 |
|--------|------|------|
| **后端语言** | PHP 8.2+ | 成熟稳定，OPcache 性能优秀，部署简单 |
| **前端框架** | 原生 JS + Alpine.js | 轻量级（15KB），响应式，学习成本低 |
| **数据库** | MySQL 8.0+ | 成熟可靠，索引优化好，社区支持强 |
| **缓存层** | Redis 7.0+ | 高性能 KV 存储，支持多种数据结构 |
| **Web 服务器** | Nginx + PHP-FPM | 高并发处理能力，静态资源优化 |

### 1.3 与 Xiuno BBS 的差异

虽然参考了 Xiuno BBS 的设计理念，但 AMuBBS 在以下方面有显著不同：

| 维度 | Xiuno BBS | AMuBBS |
|------|-----------|--------|
| **PHP 版本** | PHP 7.0+ | PHP 8.2+（利用 JIT、属性、枚举等新特性） |
| **前端框架** | Bootstrap 4 + jQuery 3 | 原生 JS + Alpine.js（极致轻量，15KB） |
| **架构模式** | MVC 混合 | 清晰的三层架构（Controller-Service-Repository） |
| **缓存策略** | 可选多种缓存 | Redis 为核心，多级缓存体系 |
| **API 设计** | 传统表单提交为主 | RESTful API 优先，支持 JSON 响应 |
| **实时通知** | 轮询 | WebSocket（Swoole/Workerman） |
| **插件系统** | Hook + Overwrite | 事件驱动 + 依赖注入 |

### 1.4 目标用户规模

- **日活用户**：1,000 - 10,000
- **并发连接**：500 - 2,000
- **数据规模**：百万级帖子，千万级回复
- **部署方式**：支持单机到主从架构的平滑扩展

### 1.5 核心功能模块

#### 基础功能
- ✅ 用户系统（注册、登录、个人中心、权限管理）
- ✅ 板块管理（多级分类、板块权限、版主系统）
- ✅ 帖子系统（发帖、回复、编辑、删除、置顶、加精）
- ✅ 富文本编辑（Markdown + 代码高亮 + 图片上传）
- ✅ 搜索功能（全文搜索、标签搜索、高级筛选）

#### 高级功能
- ✅ 实时通知（WebSocket 推送、@提醒、私信）
- ✅ 用户激励（积分、等级、勋章、签到）
- ✅ 安全防护（防灌水、敏感词过滤、IP 黑名单、验证码）
- ✅ 插件机制（动态加载、热插拔、配置管理）
- ✅ RESTful API（移动端支持、第三方集成）

### 1.6 性能指标

| 指标 | 目标值 | 测试条件 |
|------|--------|----------|
| **首页加载** | < 50ms | 100 并发，OPcache + Redis |
| **帖子列表** | < 80ms | 50 条数据，带分页 |
| **帖子详情** | < 100ms | 含 50 条回复 |
| **发帖响应** | < 150ms | 含图片上传（异步处理） |
| **搜索响应** | < 200ms | 全文搜索，10 万条数据 |
| **并发能力** | 2000 QPS | 4C8G 服务器 |

### 1.7 开发阶段规划

#### Phase 1: MVP 核心功能（4-6 周）
- 用户系统（注册、登录、基础权限）
- 板块管理（CRUD、权限控制）
- 帖子系统（发帖、回复、基础编辑）
- 简单搜索（标题搜索）
- 基础缓存（Redis 页面缓存）

#### Phase 2: 性能优化（2-3 周）
- 数据库索引优化
- 多级缓存体系
- 静态资源 CDN
- SQL 查询优化
- 压力测试与调优

#### Phase 3: 高级功能（3-4 周）
- 实时通知（WebSocket）
- 富文本编辑器集成
- 全文搜索（MySQL 全文索引或 Elasticsearch）
- 用户激励体系
- 安全防护机制

#### Phase 4: 插件与 API（2-3 周）
- 插件框架设计
- RESTful API 完善
- 移动端适配
- 第三方登录（OAuth）
- 管理后台优化

### 1.9 开发规范

#### 代码风格
- 遵循 PSR-12 编码规范
- 使用 PHP 8.2+ 新特性（属性、枚举、联合类型等）
- 类名使用 PascalCase，方法名使用 camelCase
- 常量使用 UPPER_SNAKE_CASE
