# AMuBBS 概述

> 本文说明「这是个什么项目、为什么这样选型、做了什么、明确不做什么」。
> 安装与运行请看 [`install/INSTALL.md`](../install/INSTALL.md)，架构细节看 [`02-架构.md`](02-架构.md)。
>
> 早期版本这里是带 Phase 时间线的立项文档（写着 WebSocket、Composer、MySQL 8.0+/Redis 7.0+ 强制、
> `tests/` 目录等），与实现不符，已按现状重写。

## 1.1 定位

**一个能直接扔到共享虚拟主机上的轻量论坛**：上传 → 走向导 → 用起来。

对标的是 Xiuno BBS 那类「小而快」的路线，但更彻底一点——**零第三方依赖**：
没有 Composer、没有 npm、没有构建步骤、没有必须的 Redis、没有常驻进程、没有系统 cron。

换来的取舍也很明确：不追求「功能全」，而是保证**在 1 核 1G 的小机器或几块钱的虚拟空间上跑得动**，
同时代码结构要经得起继续改（分层纪律 + 静态检查器 + 冒烟测试，见 1.6）。

## 1.2 与常见方案的差别

| 维度 | 常见论坛程序 | AMuBBS |
| --- | --- | --- |
| 依赖 | 需要 Composer 装依赖、Node 构建前端 | **零依赖**：资产手工 vendored 进 `public/assets/vendor/` |
| 缓存 | 通常强依赖 Redis/Memcached | 文件缓存为默认，Redis 可选（配了就用，没配自动降级） |
| 定时任务 | 需要系统 cron | 一次 HTTP 请求 `/cron/run?key=…` 触发全部保洁与队列任务 |
| 队列 | 需要队列服务/常驻 worker | `queue_jobs` 表 + 上面的 HTTP 触发 |
| 前端 | 框架 + 打包（React/Vue/Alpine 等） | htmx 服务端渲染片段 + 自研 CSS，**无构建步骤** |
| 部署形态 | 大多假设有 root / 能登 SSH | 目标是面板点点就能部署的共享主机 |

## 1.3 技术选型

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 后端 | PHP 8.0+，自研微框架（`core/`） | 共享主机一定支持 PHP；自研框架免去 Composer 依赖链 |
| 数据库 | MySQL 5.6+ / MariaDB 10+（PDO 预处理） | 不依赖 MySQL 8 专有特性，也不依赖 FULLTEXT |
| 缓存 | 文件驱动（默认）/ Redis（可选） | 目标环境可能根本没有 Redis，缓存必须先能落文件 |
| 会话 | 文件（默认）/ Redis | 单机零依赖；多节点时才需要 Redis 共享登录态 |
| 前台 | htmx 2.0.11 + 自研 CSS | 交互以「服务端返回片段」为主，无需前端状态管理 |
| 后台 | layuimini v2 + Layui 2.6.3 + Font Awesome 4.7 | 成熟的 iframe 多标签后台外壳，本地 vendored，不走 CDN |
| 插件 | WordPress 风格钩子（`add_action` / `apply_filters`） | 写过 WP 插件的人零成本上手；核心不需要为插件改动 |
| 队列 | `queue_jobs` 表 | 不引入 Redis 也能有「邮件/通知异步处理」 |

## 1.4 功能现状

**已实现**

- 论坛核心：板块（含子板块/权限/版主）、主题、回复、引用、编辑历史、附件上传下载
- 内容运营：置顶/加精/锁定/移动、批量操作、标签与标签分类、公告、友情链接、网址导航
- 用户体系：注册/登录/找回密码、用户组与等级、权限、签到、积分与积分日志、任务领取
- 互动：点赞、收藏、关注、私信、通知（站内 + 红点轮询）、用户动态与评论
- 搜索：关键词搜索（含中文回退策略）、按板块/类型筛选
- 安全：CSRF、登录/发帖限流、验证码、敏感词、IP 黑名单、后台 IP 白名单、两层后台认证
- 社交登录：GitHub / Google / 微信 / QQ（按后台配置决定哪些可用）
- RESTful API：15 条 `/api/*` 路由（登录注册、用户、板块、主题、回复、搜索、通知）
- 后台：27 个管理页面 + 16 个兼容用 JSON 接口
- 插件系统：后台可启停、`install()` / `uninstall()` 生命周期、坏插件隔离
- 多语言：`zh-cn` / `en-us` 语言包

**明确没有（不是没做完，是刻意不做）**

| 没有 | 原因 |
| --- | --- |
| WebSocket 实时推送 | 需要常驻进程（Swoole/Workerman），共享主机跑不了；改用轮询未读数的方案 |
| Elasticsearch / 外部全文检索 | 多一个必须运维的服务；用 FULLTEXT（可选）+ LIKE 回退足够小站使用 |
| 对象存储（OSS/S3）上传驱动 | 引入 SDK 与密钥管理；多机部署用共享目录挂载即可（见 11-扩展） |
| 富文本所见即所得编辑器 | 体积（TinyMCE 有 2.8 MB）与 XSS 风险；改为 Markdown 文本域 + 服务端渲染 |
| 自动数据库迁移 | 共享主机上「自动改表」风险大于收益；升级按 INSTALL 里的说明执行 SQL |
| 依赖注入容器 / Repository 层 | 对本站规模是纯负担；数据访问收敛到 Model 静态方法，靠检查器保证不越层 |
| 勋章体系 | 与「任务 + 等级 + 积分」重复，收益低 |

## 1.5 运行环境

| 项目 | 最低 | 建议 |
| --- | --- | --- |
| PHP | 8.0 | 8.2（开 OPcache） |
| PHP 扩展 | `pdo` `pdo_mysql` `mbstring` `json` | 另加 `redis`（可选）、`Zend OPcache` |
| 数据库 | MySQL 5.6 / MariaDB 10 | MySQL 5.7+ / MariaDB 10.11 |
| Web 服务 | 任意（面板自带的 Apache/Nginx 都行） | Apache 2.4 / Nginx 1.24 |
| 其他 | 无需 root、无需 SSH、无需 cron | 一个可写的 `storage/` 与 `public/uploads/` |

详细安装步骤与共享主机注意事项：[`install/INSTALL.md`](../install/INSTALL.md)。

## 1.6 工程约定（改代码前先看这条）

1. **分层**：Controller 管流程与响应，Service 管业务规则与事务边界，Model 管 SQL 与缓存失效。
   Controllers/Services 里写 SQL 会被 `scripts/check_layers.php` 拦下。
2. **缓存**：写入数据库后必须失效对应缓存；事务内不写缓存；SWR 闭包里不能套同一把锁。
3. **事件**：新钩子先在 `app/Events/Events.php` 定义常量，再在业务点 `Event::dispatch()`，
   最后更新 [`08-插件系统.md`](08-插件系统.md) 的钩子表；`check_events.php` 会拦「死钩子」。
4. **配置**：任何新增环境变量都要同时写进 `.env.example`（`check_env.php` 会校验双向一致）。
5. **验证**：语法 → 7 个静态检查器 → 3 个自检 → 冒烟（125 项），且必须在**无 Redis**环境下全绿。

## 1.7 目录结构

```
AMuBBS/
├── app/                    # 应用层
│   ├── Controllers/        #   17 个前台 + 16 个后台控制器
│   ├── Services/           #   26 个服务（业务规则 / 事务 / 审计）
│   ├── Models/             #   40 个模型（SQL + 缓存失效）
│   ├── Middlewares/        #   Auth / CSRF / RateLimit / RunLevel / AdminAuth
│   ├── Events/             #   30 个事件常量
│   └── Listeners/          #   事件监听器（审计日志等）
├── core/                   # 自研微框架（24 个类，含 hooks.php / Event.php / PluginManager.php）
├── config/                 # app.php / database.php / cache.php
├── plugins/                # 插件目录（Example 为示例）
├── resources/              # views（103 个模板）+ lang（zh-cn / en-us）
├── public/                 # Web 根：index.php / .htaccess / assets / uploads
├── storage/                # 运行时：cache / logs / sessions / plugin_config
├── install/                # 安装向导、database.sql（39 张表）、INSTALL.md
└── scripts/                # smoke.php + selftest_*.php + check_*.php
```

没有 `tests/` 目录：验证靠 `scripts/` 下的冒烟、自检与静态检查器（它们比单元测试更贴近
「无 Redis 环境下真的能跑」这个核心诉求）。
