## 9.1 CDN 部署方案

### 9.1.1 静态资源 CDN 化

**支持的静态资源：**
- CSS 文件
- JavaScript 文件
- 图片（用户上传的图片、头像、附件）
- 字体文件
- 其他静态文件

**CDN 配置：**

```php

```

**CDN 辅助函数：**

```php
<?php
// app/Helpers/cdn.php

/**
 * 获取 CDN URL
 */
function cdn(string $path): string
{
    $config = require __DIR__ . '/../../config/cdn.php';

    if (!$config['enabled']) {
        return $path;
    }

    $provider = $config[$config['provider']];
    $domain = rtrim($provider['domain'], '/');
    $path = ltrim($path, '/');

    return $domain . '/' . $path;
}

/**
 * 获取资源 URL（带版本号）
 */
function asset(string $path): string
{
    static $manifest = null;

    if ($manifest === null) {
        $manifestFile = APP_PATH . 'public/assets/manifest.json';
        if (file_exists($manifestFile)) {
            $manifest = json_decode(file_get_contents($manifestFile), true);
        }
    }

    // 如果有版本映射，使用带版本的文件名
    if (isset($manifest[$path])) {
        $path = $manifest[$path];
    }

    return cdn($path);
}
```

**使用示例：**

```php
<!-- 视图文件 -->
<!DOCTYPE html>
<html>
<head>
    <link rel="stylesheet" href="<?= asset('assets/css/main.css') ?>">
    <script defer src="<?= asset('assets/js/app.js') ?>"></script>
</head>
<body>
    <img src="<?= cdn('/uploads/2026/02/image.jpg') ?>" alt="图片">
</body>
</html>
```

### 9.1.2 图片上传到 CDN

```php
<?php
// app/Services/UploadService.php

namespace App\Services;

class UploadService
{
    private array $config;

    public function __construct()
    {
        $this->config = require APP_PATH . 'config/cdn.php';
    }

    /**
     * 上传图片
     */
    public function uploadImage(array $file): array
    {
        // 验证文件
        $this->validateImage($file);

        // 生成文件名
        $filename = $this->generateFilename($file['name']);
        $path = $this->getUploadPath() . '/' . $filename;

        // 上传到本地
        $localPath = APP_PATH . 'public' . $path;
        move_uploaded_file($file['tmp_name'], $localPath);

        // 如果启用 CDN，同步到 CDN
        if ($this->config['enabled']) {
            $this->syncToCDN($localPath, $path);
        }

        return [
            'url' => cdn($path),
            'path' => $path,
            'size' => filesize($localPath),
        ];
    }

    /**
     * 同步文件到 CDN
     */
    private function syncToCDN(string $localPath, string $remotePath): void
    {
        $provider = $this->config['provider'];
```

### 9.1.3 CDN 缓存刷新

```php
<?php
// app/Services/CDNService.php

namespace App\Services;

class CDNService
{
    private array $config;

    public function __construct()
    {
        $this->config = require APP_PATH . 'config/cdn.php';
    }

    /**
     * 刷新 CDN 缓存
     */
    public function purge(array $urls): bool
    {
        $provider = $this->config['provider'];

        switch ($provider) {
            case 'aliyun':
                return $this->purgeAliyun($urls);
            case 'qcloud':
                return $this->purgeQcloud($urls);
            case 'cloudflare':
                return $this->purgeCloudflare($urls);
        }

        return false;
    }

    /**
     * 刷新阿里云 CDN
     */
    private function purgeAliyun(array $urls): bool
    {
        // 使用阿里云 CDN API
        return true;
    }

    /**
     * 刷新 Cloudflare CDN
     */
    private function purgeCloudflare(array $urls): bool
    {
        $config = $this->config['cloudflare'];

        $ch = curl_init();
        curl_setopt_array($ch, [
            CURLOPT_URL => "https://api.cloudflare.com/client/v4/zones/{$config['zone_id']}/purge_cache",
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_POST => true,
            CURLOPT_HTTPHEADER => [
                'Authorization: Bearer ' . $config['api_token'],
                'Content-Type: application/json',
            ],
            CURLOPT_POSTFIELDS => json_encode(['files' => $urls]),
        ]);

        $response = curl_exec($ch);
        curl_close($ch);

        $result = json_decode($response, true);
        return $result['success'] ?? false;
    }
}
```

### 9.2.2 负载均衡配置

**Nginx 负载均衡：**

```nginx
# /etc/nginx/nginx.conf

upstream php_backend {
    # 负载均衡算法
    least_conn;  # 最少连接数
    # ip_hash;   # IP 哈希（会话保持）
    # hash $request_uri consistent;  # URL 哈希

    # Web 节点列表
    server 192.168.1.101:80 weight=3 max_fails=3 fail_timeout=30s;
    server 192.168.1.102:80 weight=2 max_fails=3 fail_timeout=30s;
    server 192.168.1.103:80 weight=1 max_fails=3 fail_timeout=30s backup;

    # 健康检查
    keepalive 32;
}

server {
    listen 80;
    server_name amubbs.com;

    location / {
        proxy_pass http://php_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 5s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 静态资源直接返回（如果使用 CDN 可以去掉）
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        proxy_pass http://php_backend;
        proxy_cache static_cache;
        proxy_cache_valid 200 30d;
        expires 30d;
    }
}

# 缓存配置
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=static_cache:100m inactive=30d max_size=1g;
```

### 9.2.3 Session 共享方案

多台 Web 节点之间必须共享登录态，否则用户在两台机器之间会被踢下线。好消息是**不用写代码**，
框架已经内置了 Redis 会话处理器 `core/RedisSessionHandler.php`，只需改环境变量：

```ini
# 每个 Web 节点的 .env（除 APP_URL 外保持一致）
SESSION_DRIVER=redis
SESSION_LIFETIME=7200      # 会话有效期（秒），也是 Redis key 的 TTL
SESSION_REDIS_DB=1         # 会话单独用一个库，方便 flush 时不影响缓存
REDIS_HOST=192.168.1.201
REDIS_PORT=6379
REDIS_PASSWORD=改成强密码
```

它做的事（真实实现）：

| 行为 | 说明 |
| --- | --- |
| 存储键 | `session:{session_id}`，写 `setex`，TTL 取 `SESSION_LIFETIME` |
| 断线处理 | 单次操作失败会**自动重连一次**再试；仍失败则记录日志并抛出「Session 存储不可用，请稍后重试」，不会静默丢登录态 |
| 驱动选择 | `SESSION_DRIVER=file`（默认）写 `storage/sessions/`；`redis` 走上面这套 |
| 无 Redis 时 | 只有显式选 `redis` 且连不上时，才会看到上面那句报错。文件驱动不依赖任何扩展 |

说明几点：

- **不需要** `config/session.php`（本项目没有这个文件），会话配置在 `config/app.php` 的 `session` 段，
  值来自 `.env`；
- **不需要**自定义 `$_COOKIE['session_id']` 处理，用的是 PHP 原生会话机制（只换了存储后端）；
- 负载均衡器**不需要**配「同一用户粘在一个节点」（没有 Redis 时才需要 ip_hash 之类的会话保持）；
- 别忘了 `admin_bind_ip` 之类的后台安全设置如果绑了单机 IP，多节点下要按实际出口 IP 调整。

**移动端 / 第三方集成**走的是另一套：`/api/*` 用 `Authorization: Bearer <token>`（无状态，
Token 哈希存在 `users.api_token`，30 天有效），与会话完全解耦，不需要共享会话。

### 9.2.5 数据库读写分离

```php
<?php
// config/database.php

return [
    'default' => 'mysql',

    'connections' => [
        'mysql' => [
            'write' => [
                'host' => '192.168.1.201', // 主库
                'port' => 3306,
            ],
            'read' => [
                [
                    'host' => '192.168.1.202', // 从库1
                    'port' => 3306,
                ],
                [
                    'host' => '192.168.1.203', // 从库2
                    'port' => 3306,
                ],
            ],
            'database' => 'amubbs',
            'username' => 'root',
            'password' => '',
            'charset' => 'utf8mb4',
        ],
    ],
];
```

```php
<?php
// core/Database.php 扩展

namespace Core;

class Database
{
    private static ?PDO $writeConnection = null;
    private static array $readConnections = [];
    private static int $readIndex = 0;

    /**
     * 获取写连接（主库）
     */
    public static function getWriteConnection(): PDO
    {
        if (self::$writeConnection === null) {
            $config = require __DIR__ . '/../config/database.php';
            $write = $config['connections']['mysql']['write'];

            self::$writeConnection = self::createConnection($write);
        }

        return self::$writeConnection;
    }

    /**
     * 获取读连接（从库，轮询）
     */
    public static function getReadConnection(): PDO
    {
        $config = require __DIR__ . '/../config/database.php';
        $reads = $config['connections']['mysql']['read'];

        // 轮询选择从库
        $index = self::$readIndex % count($reads);
        self::$readIndex++;

        if (!isset(self::$readConnections[$index])) {
            self::$readConnections[$index] = self::createConnection($reads[$index]);
        }

        return self::$readConnections[$index];
    }

    /**
     * 查询操作使用从库
     */
    public static function fetchOne(string $sql, array $params = []): ?array
    {
        $pdo = self::getReadConnection();
        $stmt = $pdo->prepare($sql);
        $stmt->execute($params);
        $result = $stmt->fetch();

        return $result ?: null;
    }

    /**
     * 写操作使用主库
     */
    public static function execute(string $sql, array $params = []): int
    {
        $pdo = self::getWriteConnection();
        $stmt = $pdo->prepare($sql);
        $stmt->execute($params);

        return $stmt->rowCount();
    }

    private static function createConnection(array $config): PDO
    {
        $dsn = sprintf(
            'mysql:host=%s;port=%d;dbname=%s;charset=utf8mb4',
            $config['host'],
            $config['port'],
            $config['database'] ?? 'amubbs'
        );

        return new PDO($dsn, $config['username'] ?? 'root', $config['password'] ?? '', [
            PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_PERSISTENT => true,
        ]);
    }
}
```

### 9.2.6 Redis 集群

**当前实现只支持单实例 Redis，没有 `redis-cluster` 驱动。** `core/Cache.php` 里的连接只有
`REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` / `REDIS_DATABASE` 四项，
也没有引用 `\RedisCluster`（早期文档里那段 `config/cache.php` 的 `redis-cluster` 配置是不存在的）。

什么时候需要 Redis 集群？到那个规模时，通常已经不用共享主机了，可选的做法：

| 做法 | 说明 |
| --- | --- |
| Redis 主从 + 哨兵（Sentinel） | 对本项目最省事：应用仍连「一个地址」，由哨兵/代理负责故障切换 |
| 客户端代理（twemproxy / Envoy Redis proxy） | 应用连代理地址，分片对代码透明 —— 同样不需要改 `Cache` |
| 真的要用 `\RedisCluster` | 属于二次开发：在 `Cache` 里加一个驱动分支，并把 `SESSION_DRIVER=redis` 的会话处理器一起改掉（会话与缓存要落在同一套集群上，否则多节点登录态仍会丢） |

无论选哪种，都建议保持一个原则：**Redis 只是加速与共享层，挂掉不能导致站点不可用**。
当前代码已经做到缓存侧自动降级文件驱动；但 `SESSION_DRIVER=redis` 时 Redis 挂掉会直接影响登录
（会话没有文件回退），这一点在生产上要靠哨兵/代理保证可用性。

## 9.3 部署清单

> 下面的配置是**规模估算的参考**，不是运行要求：本项目最低只需「PHP + MySQL + 一个可写目录」。
> 规模越小越该少装东西——**别为了小站先上 Redis 集群**。

### 9.3.1 单机 / 共享主机（小型论坛，0–1000 日活）

```
最省配置：共享虚拟主机（无 root、无 SSH）
├── PHP 8.0+（面板自带）
├── MySQL 5.6+ / MariaDB 10+（面板自带的库）
├── 缓存：文件驱动（storage/cache/），Redis 可选
├── 会话：文件（storage/sessions/）
└── 成本：几元到几十元/月

自有小机器（1C1G 起步）
├── Apache 或 Nginx + PHP-FPM
├── MySQL / MariaDB
└── 不需要 Redis、不需要 cron（用面板计划任务打 /cron/run）
```

### 9.3.2 分布式部署（中型论坛，数千日活）

```
负载均衡：1 台（2C4G）
Web 节点：2–3 台（2C4G 起，PHP-FPM + 代码）
MySQL 主从：2 台（4C8G 起，一主一从，读走 DB_READ_HOST）
Redis：1 台（2C4G，缓存 + 会话共享；单实例够用，见 9.2.6）
文件存储：NFS / 面板共享目录（挂到各节点 public/uploads/；OSS 未实现）
CDN：可选，加速 /assets/ 与 /uploads/
成本：视机房而定，通常几百到数千元/月
```

### 9.3.3 高可用部署（大型论坛）

```
负载均衡：2 台（主备或双活）
Web 节点：5+ 台
MySQL：一主多从，从库承担读；主库故障用外部方案（MHA / 编排工具）切换
Redis：主从 + 哨兵（见 9.2.6，本站不支持 \RedisCluster 直连）
文件存储：共享存储 + CDN
监控：/health 探活 + Prometheus/Grafana 或主机面板监控
```

## 9.4 部署脚本

### 9.4.1 自动化部署脚本

仓库根目录自带 `deploy.sh`（**不是** Laravel 那种 `artisan` 流程——本项目没有 Composer、没有 artisan）：

```bash
./deploy.sh               # 本机：git pull + 目录权限 + 重载 PHP-FPM + /health 检查
./deploy.sh 192.168.1.102 # 远程节点：rsync 同步后远程执行同样的动作
```

远程同步会排除「每台机器自己的状态」：`.env`、`storage/cache/*`、`storage/logs/*`、
`public/uploads/*`、`install/install.lock`。

它**不会**清应用缓存（只重载 PHP-FPM 清 OPcache），所以更新后还要：

```bash
# 1. 清应用缓存（后台「缓存管理 → 清全部」，或直接删文件）
#    文件驱动是两级分片目录 storage/cache/<xx>/<yy>/<md5>.cache，用 find 最稳
find storage/cache -name '*.cache' -delete      # .gitkeep 保留

# 2. 跑一次保洁 + 队列（重建板块统计、消费邮件/通知队列）
#    密钥只认请求头 X-Cron-Key，cron_key 没配置时接口一律 403
curl -fsS -H "X-Cron-Key: ${CRON_KEY}" "https://你的域名/cron/run"

# 3. 冒烟验证（可指向任一节点）
SMOKE_BASE_URL=https://你的域名 php scripts/smoke.php
```

### 9.4.2 健康检查脚本

节点存活用 `/health`（只暴露状态，不泄露内部信息），数据库不通时返回 500：

```bash
#!/bin/bash
# health-check.sh —— 放进任意监控/计划任务
for url in https://node1.example.com https://node2.example.com; do
  code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 "$url/health")
  if [ "$code" != "200" ]; then
    echo "[DOWN] $url -> HTTP $code"      # 这里对接你的告警通道
  else
    echo "[OK]   $url"
  fi
done
```

MySQL / Redis 的存活由 `/health` 间接覆盖（数据库不通会返回 500）；
如果 Redis 也要单独监控，用 `redis-cli -h <host> -a <pass> ping`，
但注意**Redis 挂了本站不会白屏**：缓存会自动降级为文件缓存，属于性能退化而不是故障。
