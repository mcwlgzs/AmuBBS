# 技术架构设计

> 本文描述的是**当前代码**的架构。有两点与项目最初的设计稿不同，已在正文中改正：
> 数据访问从 `App\Repositories\*`（目录已删除）收敛到 `App\Models\*` 静态方法；
> 事件系统统一为 `core/hooks.php` 的 `add_action` / `apply_filters`
> （`core/EventDispatcher.php` 已删除，见 08/10 插件文档）。

## 2.1 整体架构

### 2.1.1 架构分层


## 2.2 核心框架设计

### 2.2.1 启动引导 (Bootstrap)

```php
<?php
// core/Bootstrap.php

namespace Core;

class Bootstrap
{
    private static ?self $instance = null;
    private array $config = [];
    private Database $db;
    private Cache $cache;
    private Router $router;

    private function __construct()
    {
        // 加载配置
        $this->loadConfig();

        // 初始化核心组件
        $this->initDatabase();
        $this->initCache();
        $this->initRouter();

        // 注册错误处理
        $this->registerErrorHandler();

        // 加载插件
        $this->loadPlugins();
    }

    public static function getInstance(): self
    {
        if (self::$instance === null) {
            self::$instance = new self();
        }
        return self::$instance;
    }

    public function run(): void
    {
        // 启动 OPcache 预热
        if (function_exists('opcache_compile_file')) {
            $this->warmupOpcache();
        }

        // 路由分发
        $this->router->dispatch();
    }

    private function loadConfig(): void
    {
        $configFiles = glob(__DIR__ . '/../config/*.php');
        foreach ($configFiles as $file) {
            $key = basename($file, '.php');
            $this->config[$key] = require $file;
        }
    }

    private function warmupOpcache(): void
    {
        // 预编译核心文件
        $coreFiles = [
            __DIR__ . '/Router.php',
            __DIR__ . '/Database.php',
            __DIR__ . '/Cache.php',
        ];

        foreach ($coreFiles as $file) {
            if (file_exists($file)) {
                opcache_compile_file($file);
            }
        }
    }
}
```

### 2.2.2 路由系统 (Router)

```php
<?php
// core/Router.php

namespace Core;

class Router
{
    private array $routes = [];
    private array $middlewares = [];

    /**
     * 注册 GET 路由
     */
    public function get(string $path, callable|array $handler, array $middlewares = []): void
    {
        $this->addRoute('GET', $path, $handler, $middlewares);
    }

    /**
     * 注册 POST 路由
     */
    public function post(string $path, callable|array $handler, array $middlewares = []): void
    {
        $this->addRoute('POST', $path, $handler, $middlewares);
    }

    /**
     * 路由分发
     */
    public function dispatch(): void
    {
        $method = $_SERVER['REQUEST_METHOD'];
        $path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);

        // 查找匹配的路由
        $route = $this->matchRoute($method, $path);

        if ($route === null) {
            $this->handleNotFound();
            return;
        }

        // 执行中间件
        $this->runMiddlewares($route['middlewares']);

        // 执行控制器
        $this->runController($route['handler'], $route['params']);
    }

    /**
     * 路由匹配（支持动态参数）
     */
    private function matchRoute(string $method, string $path): ?array
    {
        foreach ($this->routes[$method] ?? [] as $route) {
            $pattern = $this->convertToRegex($route['path']);
            if (preg_match($pattern, $path, $matches)) {
                array_shift($matches); // 移除完整匹配
                return [
                    'handler' => $route['handler'],
                    'middlewares' => $route['middlewares'],
                    'params' => $matches,
                ];
            }
        }
        return null;
    }

    /**
     * 将路由路径转换为正则表达式
     * /thread/{id} => /^\/thread\/(\d+)$/
     */
    private function convertToRegex(string $path): string
    {
        $pattern = preg_replace('/\{(\w+)\}/', '(\d+)', $path);
        return '#^' . $pattern . '$#';
    }
}
```

### 2.2.3 数据库封装 (Database)

```php
<?php
// core/Database.php

namespace Core;

use PDO;
use PDOException;

class Database
{
    private static ?PDO $connection = null;
    private static array $queryLog = [];

    /**
     * 获取数据库连接（单例模式）
     */
    public static function getConnection(): PDO
    {
        if (self::$connection === null) {
            $config = require __DIR__ . '/../config/database.php';

            $dsn = sprintf(
                'mysql:host=%s;port=%d;dbname=%s;charset=utf8mb4',
                $config['host'],
                $config['port'],
                $config['database']
            );

            try {
                self::$connection = new PDO($dsn, $config['username'], $config['password'], [
                    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
                    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                    PDO::ATTR_EMULATE_PREPARES => false, // 使用真正的预处理语句
                    PDO::ATTR_PERSISTENT => true, // 持久连接
                ]);
            } catch (PDOException $e) {
                throw new \RuntimeException('数据库连接失败: ' . $e->getMessage());
            }
        }

        return self::$connection;
    }

    /**
     * 查询单条记录
     */
    public static function fetchOne(string $sql, array $params = []): ?array
    {
        $startTime = microtime(true);

        $stmt = self::getConnection()->prepare($sql);
        $stmt->execute($params);
        $result = $stmt->fetch();

        self::logQuery($sql, $params, microtime(true) - $startTime);

        return $result ?: null;
    }

    /**
     * 查询多条记录
     */
    public static function fetchAll(string $sql, array $params = []): array
    {
        $startTime = microtime(true);

        $stmt = self::getConnection()->prepare($sql);
        $stmt->execute($params);
        $result = $stmt->fetchAll();

        self::logQuery($sql, $params, microtime(true) - $startTime);

        return $result;
    }

    /**
     * 执行写操作（INSERT/UPDATE/DELETE）
     */
    public static function execute(string $sql, array $params = []): int
    {
        $startTime = microtime(true);

        $stmt = self::getConnection()->prepare($sql);
        $stmt->execute($params);
        $affectedRows = $stmt->rowCount();

        self::logQuery($sql, $params, microtime(true) - $startTime);

        return $affectedRows;
    }

    /**
     * 获取最后插入的 ID
     */
    public static function lastInsertId(): int
    {
        return (int) self::getConnection()->lastInsertId();
    }

    /**
     * 事务处理
     */
    public static function transaction(callable $callback): mixed
    {
        $pdo = self::getConnection();

        try {
            $pdo->beginTransaction();
            $result = $callback();
            $pdo->commit();
            return $result;
        } catch (\Exception $e) {
            $pdo->rollBack();
            throw $e;
        }
    }

    /**
     * 记录 SQL 查询日志（开发模式）
     */
    private static function logQuery(string $sql, array $params, float $time): void
    {
        if (defined('DEBUG') && DEBUG) {
            self::$queryLog[] = [
                'sql' => $sql,
                'params' => $params,
                'time' => round($time * 1000, 2) . 'ms',
            ];
        }
    }

    /**
     * 获取查询日志
     */
    public static function getQueryLog(): array
    {
        return self::$queryLog;
    }
}
```

### 2.2.4 缓存系统 (Cache)

> 本节按**当前实现**重写。早期草稿写的是一个只用 Redis 的 `Cache` 类
> （到处 `getRedis()->setex()/sAdd()`），与代码不符，也违背「无 Redis 也能跑」这个核心约束。
> 真实实现在 `core/Cache.php` + `core/Cache/FileStore.php`。

#### 设计要点

1. **驱动可切换**：`CACHE_DRIVER=auto|file|redis`。
   `auto` 会探测 Redis 扩展是否可用，不可用就用文件驱动；连不上也**自动降级**而不是白屏。
2. **API 与驱动无关**：业务代码只调 `Cache::get/set/delete/...`，不感知底层是文件还是 Redis。
   这是「同一份代码既能在共享主机跑、也能在多机 + Redis 跑」的前提。
3. **文件驱动只依赖一个可写目录**：`storage/cache/`，按 `md5(key)` 两级分片存放（`<h0h1>/<h2h3>/<md5>.cache`，避免单目录塞满几十万文件），
   文件头里存原始 key（便于 `deletePattern` 与人工排查）。
4. **键版本化**：缓存键统一带 `v1:` 前缀，改数据结构时整体升版本即可让旧缓存自然失效，
   不需要写迁移脚本。

#### 常用 API

| 方法 | 说明 |
| --- | --- |
| `Cache::get($key, $callback = null, $ttl = 3600)` | 读；未命中且给了回调就回源并写入 |
| `Cache::set($key, $value, $ttl)` / `Cache::delete($key)` | 写 / 删 |
| `Cache::deleteMulti(array $keys)` / `Cache::deletePattern($pattern)` | 批量删 / 按前缀删 |
| `Cache::add($key, $value, $ttl)` | 仅当键不存在时写入（用于锁、防重复提交） |
| `Cache::increment($key, $step, $ttl)` | 原子自增（计数、浏览量） |
| `Cache::incrementWithLimit($key, $limit, $ttl)` | 原子「自增并判断是否超限」，限流中间件用它，超限返回 `-1` |
| `Cache::getAndDelete($key)` | 取一次即删（验证码、一次性令牌） |
| `Cache::getStale($key, $callback, $ttl, $staleTtl)` | **SWR**：先返回旧值，再重建（首页列表用，避免缓存过期瞬间的毛刺） |
| `Cache::batchIncrement(array $pairs)` / `Cache::preload(array $keys)` | 批量自增 / 批量预热（减少往返） |
| `Cache::gc()` / `Cache::flush()` | 清理过期文件 / 清空（后台「缓存管理」用） |

#### 读路径（简化）

```php
public static function get(string $key, ?callable $callback = null, int $ttl = 3600)
{
    $key = self::versionKey($key);              // 统一加 v1: 前缀
    $value = self::store()->get($key);          // FileStore 或 RedisStore

    if ($value !== null) {
        return $value;
    }
    if ($callback === null) {
        return null;
    }

    $value = $callback();                       // 回源
    self::store()->set($key, $value, $ttl);
    return $value;
}
```

#### 三个必须知道的坑（都踩过）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| **空结果也会被缓存** | 查不到的记录（`fetchOneCached` 返回 `null`）被缓存后，即使后来真的有了也一直「查不到」 | 写入方必须显式失效对应缓存；模型层提供 `forgetOne/forgetAll` |
| **SWR 闭包里套同一把锁** | 在 `Cache::getStale('forums:list', …)` 的闭包里再调 `childrenCached()`（同一 key 的 SWR）会拿到**空数组** | 这种场景改用裸查询（`Forum::childrenRows()`），模型里已刻意保留 |
| **文件驱动的「按内容搜索 key」** | 文件名的 `md5(key)` 里看不到 key 本身，早期按内容搜 key 的清理逻辑一个文件都删不掉 | 文件头里存原始 key；清理一律走 `deletePattern()` |

#### 无 Redis 时的行为

| 场景 | 行为 |
| --- | --- |
| 没有 `redis` 扩展 | 启动时提示一次并降级到文件驱动（`error_log`），功能不变 |
| `CACHE_DRIVER=redis` 但连不上 | 连接失败即降级文件缓存，页面照常；`error_log` 记录原因 |
| 缓存目录不可写 | 再降级为「进程内缓存」（本次请求有效），并记日志 |
| 限流后端不可用 | **放行本次请求**（宁可少拦一次，也不误伤正常用户） |

文件缓存的过期清理是**惰性的**：每次写入有 `1/CACHE_FILE_GC`（默认 200）的概率触发一次 GC，
所以不需要任何定时任务；`/cron/run` 只是额外提供了一个定期清理入口。

## 2.3 分层实现（实际代码）

> 本节描述的是**当前代码的真实分层**。早期设计稿里的「Controller → Service → Repository」
> 三层已经在重构中合并为「Controller + Model」两层：`app/Repositories/` 目录已删除，
> 数据访问（SQL + 缓存失效）全部收在 `App\Models\*` 的静态方法里。

### 2.3.1 三层职责

| 层 | 目录 | 负责 | 不负责 |
| --- | --- | --- | --- |
| Controller | `app/Controllers/`（后台 `app/Controllers/Admin/`） | 取参数、鉴权、调 Service、渲染视图（前台组织 htmx 片段响应，后台回 JSON `{code, msg}`） | **不写 SQL、不碰 Database** |
| Service | `app/Services/*Svc.php` | 跨表业务规则、审计日志、事务边界、缓存失效编排 | **不写 SQL**（只有事务/连接控制） |
| Model | `app/Models/*.php` | SQL、行级缓存 key 的读写与失效、软删除、统计字段维护 | 不写业务规则、不发通知、不记审计日志 |

这条纪律不是口头约定，而是 `scripts/check_layers.php` 强制的：
Controllers / Services 里出现 `Database::(execute|fetchAll|fetchOne|fetchAllCached|fetchOneCached|insert|update|delete|query|prepare|lastInsertId)`
或 `new PDO` 就报错退出（当前唯一的两处例外写在脚本里，并带原因注释）。

### 2.3.2 Controller 层

前后台共用一套 `App\Controllers\Base`（后台 `AdminBase` 继承它），但响应形态不同：
**htmx 片段只服务前台**，后台走 JSON `{code, msg}`（见 [`12-后台.md`](./12-后台.md) 的交互约定）。

```php
// 前台：Base 提供这些约定
$this->isHtmx();                 // 是否 htmx 请求
$this->input();                  // 合并 POST / JSON body
$this->respondFragment($ok, $msg);            // HX-Reswap: none + HX-Trigger 提示
$this->respondSubmit($ok, $msg, $redirect);   // 成功回 HX-Redirect
$this->respondRefresh($ok, $msg);             // 让前端刷新当前区域

// 后台：AdminBase（layuimini iframe 子页面，不使用 htmx）
$this->renderAdmin('admin/xxx', $data, 'xxx'); // 渲染 layout_child 完整子文档
$this->respondMutation($ok, $msg, fn() => $this->renderXxxPage()); // 默认走 JSON {code, msg}
```

约定要点（以下三条只适用于**前台** htmx；后台不用 htmx）：

- **提示走 `HX-Trigger`**，中文必须经 `json_encode` 转成 `\uXXXX`：
  HTTP 头按 ISO-8859-1 解码，直接塞 UTF-8 中文会变乱码。
- **失败统一 422 + `HX-Reswap: none`**，不换 DOM，只弹提示。
- 后台是 layuimini 的 **iframe 多标签**外壳：每个子页面由 `resources/views/admin/layout_child.php`
  渲染成**完整文档**、装进 iframe（`AdminBase::renderAdmin()` 已没有 htmx 片段分支），
  所以刷新子页面不会重建外壳、切换 tab 也不会重复请求页面；外壳（tab / 菜单 / 顶栏）
  由 `/admin` 这条路由单独渲染 `admin/layout`。后台的变更接口统一回 JSON `{code, msg}`。

### 2.3.3 Service 层

`app/Services/` 现在只剩「业务编排」，数据访问已经清空（`check_layers` 保证）。
服务层里出现的 `Database::` 调用**全是事务与连接控制**：

```php
Database::beginTransaction();
try {
    // 调模型方法（模型内部管 SQL 与缓存失效）
    $threadId = Thread::create($forumId, $userId, $username, $title, $content);
    $this->forumService->onThreadCreated($forumId, $threadId);
    Database::commit();
} catch (\Throwable $e) {
    Database::rollBack();
    throw $e;
}

// 事务提交之后再做：缓存清理、事件派发、生命周期钩子
Event::dispatch(Events::THREAD_CREATED, ['thread_id' => $threadId, ...]);
```

纪律：

- **缓存写入不放在事务里**：事务回滚后缓存可能已经脏了。
- **事件派发放在提交之后**：插件回调里再开事务会撞上未结束的事务。
- 事务里只做「必须原子」的写；通知、计数奖励、日志等放事务外。

### 2.3.4 Model 层

`App\Models\Model` 是抽象基类，子类实现静态方法，约定：

```php
abstract class Model
{
    protected static string $table = '';
    // 表没有 deleted_at 列时显式声明为 null，避免误加 deleted_at IS NULL
    protected static ?string $softDeleteColumn = 'deleted_at';
}
```

基类提供的缓存工具（按用途选，选错会踩坑）：

| 方法 | 用途 |
| --- | --- |
| `cachedOne($sql, $params, $ttl)` / `cachedAll(...)` | 普通读写缓存 |
| `staleAll($key, $sql, $params, $ttl)` | SWR（先返回旧值，后台重建），首页列表用 |
| `staleFetch / staleOne / staleCount` | 同上，取一条 / 计数 |
| `forgetOne / forgetAll` | 按 SQL 失效对应缓存（写入后必须调） |
| `existsWhere / softDeleteById` | 存在性判断 / 软删除（同时失效缓存） |
| `keyedOne / dailyCounts` | 按 key 取一行 / 今日计数 |

两个必须知道的坑：

1. **`fetchOneCached` 会把 `null` 也缓存**（用 `_v => N` 区分空结果），
   所以「查不到」也有缓存，写操作后必须显式失效，否则会一直返回「不存在」。
2. **SWR 闭包里不能再套同一 key 的 SWR**：
   `Cache::getStale('forums:list', ...)` 的闭包里如果调用 `childrenCached()`（同一把锁），
   重建过程会拿到空值。所以模型里刻意留了 `childrenRows()`（裸查询）给这种场景用。

### 2.3.5 数据访问与分层的自动化把关

重构能保持不退化，靠的是 7 个静态检查脚本（都返回非零退出码，可直接进 CI）：

| 脚本 | 守住什么 | 为什么需要 |
| --- | --- | --- |
| `check_layers.php` | Controllers / Services 里不得出现数据访问 | 防止 SQL 慢慢爬回上层（历史上就这样退化的） |
| `check_imports.php` | 模型 `use` 是否漏写/多余 | 漏 `use` 会在运行时 500，`php -l` 查不出来 |
| `check_routes.php` | 每条路由指向的控制器方法是否真实存在 | 整块替换代码时删掉过入口方法（NotifyController 事件） |
| `check_schema.php` | 代码引用的表是否都在安装脚本/运行库里 | `social_logins` 建表漏了，装了站永远跑不通社交登录 |
| `check_events.php` | 每个事件常量是否真有派发点、是否引用了未定义常量 | 6 个事件长期「定义了但永不触发」，插件挂上去没反应 |
| `check_env.php` | `.env.example` 与代码读取的配置项是否一致 | 曾有一批「文档里写了、代码根本不读」的死配置（`APP_MODE` / `UPLOAD_DRIVER` / `OSS_*`） |
| `check_docs.php` | 文档的代码围栏是否成对、文档内链接是否有效 | 按行号拼接重写文档时残留过孤立代码片段与未闭合围栏，渲染整篇变代码块 |

加上 `scripts/smoke.php`（125 项真实 HTTP 冒烟）与 3 个 `selftest_*.php`（缓存 / 钩子 / 安装），
每次改动后的验证组合是：**语法全量 → 静态检查 → 自检 → 冒烟 → 数据基线**。

整条链路已封装成一条命令，返回非零退出码即失败，可直接进 CI：

```bash
bash scripts/verify.sh                        # Linux / macOS / CI
powershell scripts/verify.ps1                 # Windows
SKIP_SMOKE=1 bash scripts/verify.sh           # 没起服务时只跑静态检查 + 自检
SMOKE_BASE_URL=https://你的域名 bash scripts/verify.sh   # 验证线上节点
```

### 2.3.6 一次「发帖」请求的完整链路（示例）

```
POST /thread/create
  └─ Middlewares: Csrf → RunLevel(等级) → Auth
       └─ Controllers\Thread::create()
            ├─ 取参、校验标题/内容长度、验证码、板块权限
            ├─ Services\ThreadSvc::createThread()
            │    ├─ 防灌水 / IP 频率（Cache）
            │    ├─ 敏感词过滤（Services\SensitiveWordService）
            │    ├─ apply_filters('thread.title' / 'post.content')   ← 插件过滤器
            │    ├─ 事务：Thread::create() + Forum::adjustXxx() + User::incrementThreadCount()
            │    ├─ 事务外：积分奖励、清缓存、等级自动升级、@提醒
            │    └─ Event::dispatch(Events::THREAD_CREATED, [...])   ← 插件动作
            └─ respondSubmit(true, '发帖成功', '/thread/{id}')
```

分层到这里就是一句话：**Controller 管流程，Service 管规则，Model 管数据与缓存**，
插件的两原语（`add_action` / `apply_filters`）只挂在业务点上，不需要知道自己被谁调用。
